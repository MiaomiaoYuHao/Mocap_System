# 原始数据流录制（.pcrec）—— 录什么、怎么录、我拿到之后怎么调参

## 0. 一句话

面板上选协议 → 点「● 录制」→ 做规定动作 → 点「■ 停止」→
**先自己体检** `python3 tools/pcrec/pcrec.py check 你的文件.pcrec` → 通过了再发我。

---

## 1. 先说清楚一件事：没有真值就没有「最优参数」

你现在的参数是"随便调的"，我要"搜出一套最优"。但最优是相对某个**目标函数**而言的，
而目标函数需要真值。仿真里我有真值（`hand_rig.py` 直接给 `seg_R`），**真机没有**。

所以这套录制格式的核心设计不是"把数据存下来"，而是**让每一段数据自带一组物理不变量**，
用不变量当近似真值。这就是「协议」那个下拉框的全部意义。

| 协议 | 你要做的 | 它给出的不变量（= 我的目标函数） |
|---|---|---|
| **静止保持** | 手架稳完全不动，15 秒 | 一切变化都是噪声。直接量位置抖动、四元数抖动、标签翻转率 |
| **刚体运动** ⭐ | 手型固定住（**手指别动**），整只手平移+转动，30 秒 | 20 点两两距离**全部恒定** → 190 个约束。可测位置误差、标签错误、遮挡补全质量 |
| **手指屈伸** | 手掌位置基本不动，五指反复屈伸/张合，30 秒 | 骨长恒定 + 手背刚体 → 标 IK 参数、自标定收敛性 |
| **遮挡压力** | 故意用另一只手/物体挡住部分球，并转到极端角度，30 秒 | 标签稳定性、鬼点率、重捕延迟 |
| **自由动作** | 你实际应用里的动作，60 秒 | 综合表现。可用不变量最少，只能当验证集不能当训练集 |
| **刚体标定件** | 贴了 3~5 颗球、**球间距已知**的杆，30 秒 | **真·真值**。能标三角化和 IEKF 的绝对精度 |

⭐ **「刚体运动」这一段最有价值，务必录。** 190 个恒定距离约束几乎等价于真值，
而且它对所有参数都敏感（2D 检测、三角化、IEKF、关联、滤波全都会破坏刚体性）。

**最少录这三段**：静止保持 + 刚体运动 + 手指屈伸。
**推荐五段全录**，每段一个文件，加起来不到 3 分钟。

如果你手上有刚体标定件（哪怕是自己在一根铝条上贴 4 颗球、用卡尺量出间距），
录一段并把间距写在「备注」里 —— 那是这里唯一的绝对真值，价值超过其他所有段。

## 2. 为什么要存 2D 光斑，而不只是 3D 点

你的系统有**两级**独立可调：

```
2D光斑(每相机+时间戳+协方差) --[IekfPointTracker，约30个参数]--> 3D候选点
3D候选点 --[hm20关联 + IK + 滤波 + 自标定]--> 骨架
```

只存 3D 点的话，第一级那三十个参数（关联距离、位置/速度过程噪声、马氏门、卡方门、
密度门、机动自适应 Q、双锚门、鬼点抑制……）**一个都调不了**，因为它们的输入没被保存。

所以格式里两级都存，外加**当前参数下的骨架输出作为基线**。基线的作用是：
离线复算时先跟基线比对，对得上才说明我的复现跟你的在线系统是同一回事。
这一步不做，后面所有调参结论都不可信。

## 3. 录制时的注意事项

1. **先让系统进入正常工作状态再按录制。** 相机曝光稳定、手已经在视野里、
   骨架叠加已经在正常显示。录一段"系统还没热起来"的数据没有意义。
2. **中途别改参数。** 真要改，改完会自动写一条 ParamDelta 记录，但分析时那一段
   要单独切出来，很麻烦。宁可停下来重录。
3. **用「打标记」切段。** 手抖了、走神了、有人从镜头前走过 —— 当场按一下标记，
   备注写"作废"。事后靠时间猜哪段坏了非常不可靠。
4. **看着「丢块」那个数。** 不为 0 说明磁盘跟不上，数据有洞。换 SSD，
   或者只录 3D（把 2D 那部分关掉——不过那样 IEKF 参数就调不了了）。
5. **每段单独一个文件。** 不要一个文件里混多个协议。

## 4. 体检

```
python3 tools/pcrec/pcrec.py check pcrec_刚体运动_20260807_143022.pcrec
```

会打印时长、相机数、每帧点数、帧间隔、骨架有效率、手背 Kabsch 残差，
以及协议专属检查（比如刚体段会直接算 20 点两两距离的跨帧标准差 —— 如果 p90 > 8mm，
说明你手指动了，这段当不了刚体真值，建议重录）。

**看到 `✗ 不可用` 就别发了**，先按提示解决。看到 `⚠ 警告` 可以发，但告诉我你知道。

导出成 npz 随手看：`python3 tools/pcrec/pcrec.py dump 文件.pcrec`

## 5. 我拿到之后会做什么

1. **对齐验证**：拿录制里的 2D 光斑重跑三角化+IEKF，比对录制里的 3D 点；
   再拿 3D 点重跑关联，比对录制里的骨架基线。对不上就先修复现，不谈调参。
2. **建目标函数**：按协议组装不变量残差 —— 刚体段的 190 个距离方差、静止段的抖动、
   屈伸段的骨长方差、遮挡段的标签翻转率，加上通用项（重投影残差、鬼点率、认领率、
   手背 Kabsch 残差、IK 残差、时序连续性）。
3. **分层搜索**：先搜第一级（IEKF），因为第二级的输入取决于它；固定第一级的最优解
   之后再搜第二级。同层内用坐标下降 + 局部随机重启，不用全网格 —— 三十个参数的
   全网格是天文数字。
4. **留验证集**：用「自由动作」那段做 held-out，防止在刚体段上过拟合。
   如果最优参数在自由动作上明显变差，我会告诉你，而不是把过拟合的结果给你。

## 5.5 相机数变了怎么办（3 台 → 更多）

**结论先说**：参数分三类，只有第三类需要重调。

| 类别 | 例子 | 加相机后 |
|---|---|---|
| **个体参数** | anchor、骨长、thumbAxialK、手背模板 | **完全不用改**。这些是"你这只手长什么样"，跟机位无关 |
| **动力学参数** | One-Euro 的 beta（跟手速挂钩）、maxMissedFrames（跟遮挡时长挂钩） | **基本不用改**。手的运动学没变 |
| **噪声/几何参数** | assocDist、过程噪声、马氏门、卡方门、maxFinalResidual、twoViewMinRayAngle、密度门、鬼点抑制 | **必须重调**。它们编码的是"3D 点有多准、幽灵点有多多" |

三台相机是一个**质变的工况**，不只是"少一点精度"：

- 每个 marker 要被 ≥2 台看到才能三角化。三台时掉一个视角就只剩两视角，
  而**两视角三角化在深度方向条件极差、且极易产生幽灵点**（两条视线的伪交点）。
  幽灵点数量随"只有两视角的点占比"急剧上升，而这个占比在三台时通常很高。
- 遮挡率高得多 → 网络的 `pos` 头（遮挡预测）承担的比重大得多 →
  `minAssignProb` 这类阈值的最优值会偏低。
- 自标定的门（手背 5 点全见 + 手指 ≥8 点）更难满足 → 标定耗时明显变长。

体检脚本会直接打印**每点支持视角数**和**两视角占比**。两视角占比超过 40% 时会报警告 ——
那说明瓶颈是机位而不是参数，这时候再怎么调参收益都有限。

### 我会怎么交付参数，让你以后少受一次罪

不给你一堆写死的数字，而是**把噪声相关的阈值表达成实测噪声底 σ 的倍数**。
`σ` 由系统自己每帧测得到（重投影残差 + 手背 Kabsch 残差，两者录制里都存了）。
这样加相机时 σ 自动变小，阈值跟着自动收紧，不用人工重调。

我在自标定里已经这么做了一处：模板校验阈值是 `max(1.2mm, 2.5σ)` 而不是固定毫米数
（固定值实测两头不讨好：设松了放过标错的模板，设紧了噪声大的现场永远标不成）。
调参交付时我会把同样的处理推广到 IEKF 那几个门。

### 加相机时你要做的（大约 5 分钟）

1. 重录一遍那三段协议（静止 / 刚体 / 屈伸），发我。
2. 我重算 σ 和两视角占比，更新倍数系数——**通常只需要改 3~5 个数，不是全部重搜**。

### 一个只有现在能做的事

`.pcrec` 里存了**每个点被哪几台相机看到**（`supportMask`）。所以：

> **等你加到 5~6 台之后，录一段全相机的数据，我可以离线关掉任意几台重跑，
> 一次性得到 3/4/5/6 台的完整精度曲线。**

那时候"再加一台值不值"就不再是拍脑袋，而是能直接看到边际收益拐点在哪。
现在只有三台做不了消融（不能凭空造出第四台），但格式已经为此留好了。

## 6. 文件格式（给要自己写解析的人）

```
"MCPCREC\0"          8 字节
uint32 version       = 1
uint32 headerLen
<headerLen 字节 UTF-8 JSON>   协议/备注/相机列表/参数快照/创建时间
然后是块流，每块： uint8 type, uint32 payloadLen, payload
  type 1 CamBlobs    uint32 camId, int64 tsNs, uint16 n, n×Blob2D(24B)
  type 2 Points3D    int64 tsNs, uint16 n, n×Point3DRec(24B)
  type 3 Skeleton    int64 tsNs, SkeletonRec(668B)
  type 4 Mark        int64 tsNs, uint8 kind, uint16 len, utf8
  type 5 ParamDelta  int64 tsNs, uint32 len, utf8 json（相机内外参也走这个，只写一次）
  type 6 Cluster3D   int64 tsNs, uint16 n, n×ClusterRec(24B)
                     多视角匹配的原始输出（追踪之前）。带 supportMask=哪几台相机
                     贡献了观测、residualPx=重投影残差。【离线相机消融靠它】
```

小端。每块自带长度，所以**录制中途崩溃/断电的文件依然能读到最后一个完整块**——
录制场景下这个比校验和重要得多。`pcrec.py` 会把这种文件标为 `truncated` 但照常解析。
