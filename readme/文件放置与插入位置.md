# 文件放哪里 · 代码插哪里

> 先说一个改动：`DorsumRigidSolver.hpp` 我改成**零依赖**了。
> 原来那版 `#include "estimate/HandSkeletonAssociator.hpp"`，而关联器又要拿它当成员 —— 循环 include，
> 谁先被包含谁就编不过。现在它自带一份最小数学（`drs` 命名空间，Horn 四元数法的 Kabsch），
> **两个头文件谁先 include 都行**，我两种顺序都 `-fsyntax-only` 验过。
> `drs::V3` / `drs::M9` 跟关联器的 `Vec3` / `Mat3` 是**同一个类型**（`static_assert` 验过），可直接互传，不用转换。
> 换掉 Kabsch 实现之后蒙特卡洛的数一位没变，说明是等价替换。

> 一个"面板切手性 → 拇指 IK 突然全废"的坑。

### 5.3 手性一致性的一个既有隐患（顺手修，不修也能跑）

`applyAutoCalib()` 里（**第 593 行附近**）会 `ik->setHandedness(tmpl_.isRight)`，
而 `tmpl_.isRight` 在 `applyHandedness` 打开时可能是自标定**推断**的值；
但 `assoc_->setThumbPronation(sgn * ...)` 那个 `sgn` 用的是**面板**的 `handIsRight_`。
两者可以不一致 —— IK 按左手解、拇指旋前按右手补。

改法：把 `sgn` 的来源统一成 `tmpl_.isRight`：

```cpp
            const double sgn = tmpl_.isRight ? 1.0 : -1.0;
```

（`applyHandedness` 默认关着时两者恒等，所以这条现在多半没触发；等你哪天打开它才会炸。）

## 六、UI（`PointCloudTestDialog.cpp`）—— 最少改动版

如果暂时不想动 Qt 层，**可以完全不改**：
`dorsumRigidSolve` 默认 true、`dorsumTracklet` 默认 false，直接就生效了。
只是面板上看不到新的诊断数。

想看数的话，找诊断栏那几行 `.arg(diag.xxx)`，加一行：

```
手背刚体 内点%1/5  残差%2mm  裕度%3mm%4   自歧义%5mm
```

分别喂 `dorsumSolveReason==0 ? nMatched : 0`、`dorsumGeoRmseMm`、`dorsumGeoMarginMm`、
`dorsumUsedHistory ? "[连续性]" : ""`、`dorsumSelfAmbiguityMm()`。

**「自歧义」那个数是这次最该被显示出来的。** 它一次算完不变，
但它决定了你这只手到底能不能被稳定定标签 —— `< 3mm` 就该去重贴点，
而不是继续在软件里想办法。

## 七、编译顺序建议

分两批，别一次全上：

**第一批（手背）**：一、二、三节 + 五节的 5.1/5.2。
编完跑 `./test_dorsum_rigid_mc`，确认"错标"那列在有历史时是 0.000。
然后开机看连线 —— 钉住的点应该当场消失。

**第二批（拇指）**：四节 + 五节的 5.1 后半。
`thumbPronation0` 先填 **0** 编译（等价于旧行为，只验证没编坏），
再做 README 3.2 节那个 `-1.5 / 0 / +1.5` 的 A/B，看 `fingerIkRmseMm[0]`。

两批之间的状态是可用的，不会出现"改到一半跑不起来"。
