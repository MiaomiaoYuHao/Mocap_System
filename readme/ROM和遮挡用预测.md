# ROM 标定 + 遮挡时用预测值

两件都用你的握拳素材（889 帧）验过了。

---

# 一、ROM"行程太短"：根因跟行程无关

`observe()` 里 `if (!r.fingerValid[f]) continue;`，而 `fingerValid` 要求
`measured()`，后者只认几何解和 IK 解、**`Predicted` 不算**。

**握拳时中远节球正好被手掌挡住**：

```
指0 三点全可见 59.1%    指2 只有 30.0%
诊断里 ikFallback 中位 8，74% 的帧有遮挡补点
```

**你握得越用力，采到的样本越少。** 这是死结。

```
                每维样本数              达标      coverage
修复前   拇525 食445 中276 无301 小309   11/11      51%
修复后   全部 889 帧                     11/11      60%
```

修法：加 `romRelaxed` 参数，只在标定期间放行 Predicted。
ROM 取 p2/p98 分位对个别坏样本免疫，而补出来的点已经过链式续解 + 骨长回正。

# 二、遮挡时用预测值（你说的那件）

**你说得对，而且差距比我预期的大。** 恢复瞬间的角度 vs 恢复后的实测真值：

|  | 冻结上一帧（旧） | 用预测值 |
|---|---|---|
| 握拳段 中位 | **20.71°** | **1.64°** |
| 握拳段 p90 | 51.99° | 22.00° |
| 运动段 中位 | 3.42° | **0.36°** |
| 运动段 p90 | 22.13° | **1.02°** |

握拳时冻结的中位误差 **20.7°** —— 那正是"手指弯下去机械手卡住不动"。

## 为什么现在敢用了

写下那个 gate 的时候预测确实不可信。之后陆续加了：
链式续解、骨长回正（回正后与标定值偏差恒为 **0.000mm**）、
位置平滑、恢复补偿。现在预测位置在恢复瞬间的中位误差只有 6.4mm。

## 代价：抖动上去了，加了一层角度平滑

接受预测后角度二阶差分 p95 从 2.81° 涨到 6.77°。

**位置平滑之后仍然需要角度平滑**：关节角是两个骨轴的夹角，
两端各自的残余抖动在求角时会放大，骨越短越明显。

扫描（两个判据一起看）：

```
                    抖动p95   恢复误差中位
冻结上一帧（旧）      2.81°       20.71°
用预测 alpha=1.00     6.77°        1.64°
用预测 alpha=0.50     4.28°        3.34°   <- 取这个
用预测 alpha=0.35     3.71°        4.72°
用预测 alpha=0.20     3.30°        9.29°
```

0.5 处抖动降 37%，恢复误差仍比冻结好 **6 倍**。

**冻结的 2.81° 不是"更平稳"** —— 它帧间中位是 0.00°，因为它根本不动。
拿不动换平稳没有意义。

`ROM 采样用平滑前的值` —— 平滑会把行程两端往里收，标出来的区间偏窄。

# 三、两个查错又撤回的判断

**① 以为 ROM 失败是 PIP 压缩 bug 造成的。**
回退那个修复重跑同一段素材，两版都 `finish()=成功`，
而且**旧版 coverage 反而更高**（60% vs 51%）。不成立。

**② 以为 PIP 全负是符号反了。**
ROM 表里 `食PIP lo=-23.8` 而限位 `[0,110]`，看着像符号错。
查真实数据：带符号 PIP **负值只占 5%**、中位 +16.0°，符号是对的。
`lo` 为负是分位数下端（手伸直的时刻），正常。

# 四、顺带发现、没修的

大误差样本全集中在**维1 = 拇CMC展**，真值算出 104°/177°，
而限位是 `[-10, 66]`——**拇指外展出现了物理不可能的角度**。

那一维是 `atan2` 的方位角，拇指掌骨方向特殊时会绕圈。
两条路（冻结/预测）都受影响，不是"用不用预测"能决定的。
需要单独处理，这次没动。
