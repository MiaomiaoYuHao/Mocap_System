# 「明明识别到了也对了，为什么还显示预测」

## 是我上一轮引入的 bug

蓝色空心方块 = `!observed`。而刚体求解**没通过**时，我把 5 个手背点全标成未观测，
但**没动它们的位置** —— 位置还是网络标好的那份，通常是对的。
于是画面上位置正确、连线正确，却被画成"预测"。

那为什么刚体求解会不通过？**我上一轮做性能优化时写坏了。**

### bug 本体

加空间门控时，我用正则把函数内的 `pts[...]` 和 `pts.size()` 换成了门控后的 `P`，
但**漏掉了作为函数参数裸传的那个**：

```cpp
greedyMatch(proj, pts, M, cfg_.inlierTolMm, asg);
//                 ^^^ 未门控的数组，但 M 是门控后的大小
```

在错误的数组上按错误的长度收内点，结果就是求解器从**门控生效那一刻起再没解出来过**。

### 对照实验

杂点散布 ±300mm、门控半径 70mm（门控真的会过滤），手背点故意放在数组末尾：

| | 正确 | 错标 | 拒解 |
|---|---|---|---|
| **有 bug** | 1 | 0 | **599** |
| **修复后** | **600** | 0 | 0 |

600 帧里 599 帧拒解 —— 跟你截图的症状完全一致。

时间点也对得上：你这个构建是修完 `Hm20AutoCalib` 编译错误后的第一个，
也是**第一个包含空间门控的构建**。

## 为什么我之前的测试没抓到

我原有的蒙特卡洛里，杂点散布 ±60mm、门控半径 70mm —— **门控几乎不过滤**，
`P` 和 `pts` 基本相同，下标空间没差异，bug 不会暴露。

所以我上一轮报的"准确率逐行一致"是真的，但它**没有覆盖新加的代码路径**。
新写了 `test_dorsum_gating.cpp` 专门测这个：杂点散得很开、手背点放数组末尾，
下标映射错了必然标错。

## 顺带：显示改成三档

即使求解正常，还是有区分的必要。原来只按 `observed` 分两档，
把两种完全不同的状态混成了一种：

| 状态 | 原来 | 现在 |
|---|---|---|
| 真的没这个点，位置是补出来的 | 蓝方块 | 蓝方块（正确） |
| 点是真的、模型标对了，只是这一帧几何没验过 | 蓝方块（误导） | 橙圆点 |

用 `confidence` 区分：`>0` 说明 `sourcePointId` 指向一个真实存在的候选点。
`!r.ok` 分支不再清掉 `sourcePointId` —— 那个 id 是有意义的，清掉等于丢信息。
