# 手背修不回来、必须重开面板

## 查到的原因：三个"进去出不来"的状态

| 状态 | 问题 |
|---|---|
| `hasPrev_` / `prevR_` | 连续性仲裁一旦锁到错的分支，会**永远偏向它**。`resetHistory()` 存在，但**没有任何地方调用** |
| `tmpl_` | 只在 `!templateValid()` 时设一次。被一次错误的重捕改坏之后**没有回头路** |
| `observeForRepair` | 要求 `r.ok`。求解失败 → 不能重捕 → 一直失败，**死锁** |

重开面板等于重建整个关联器 —— 那是当时**唯一**的复位路径。这就是你观察到的现象。

---

## 我做了什么，以及哪些是可靠的

### ✅ 可靠：「手背复位」按钮

面板上"右手"复选框旁边新增。点一下清掉上面三个状态：连续性锁、重捕缓冲、
被重捕改过的模板（退回标定值）。

**等价于重开面板，但不会连带丢掉自标定和 IK 的状态** —— 那两个重新收敛要几十秒。

这个是确定有效的：它做的就是重开面板做的那件事，只是范围收窄了。

### ⚠️ 不确定：自动看门狗

加了两级自动恢复（连续 20 帧解不好 → 松锁；连续 90 帧 → 退回模板），
另外用手指落点做持续校验（残差判不出"标签排错"，因为排错的解残差往往是好的）。

**但我没能构造出你那个真实场景，所以不敢说它能修好你遇到的那个。**

我造了一个死锁（标签从第 60 帧起错、**从未恢复** —— 见 `test_dorsum_lockin.cpp`），
但看门狗也没救回来：那一版里手指落点只有 1.4~3.7mm，拟合是好的。
说明我造的是"点挪到另一个槽位附近所以被认成别的槽"，姿态本身没错 ——
跟你说的"连线全乱"不是一回事。

看门狗能解决的是**第三条**（求解一直失败的死锁），那条是确定的。
前两条要靠按钮，或者等我拿到能复现的录制。

## 帮我定位它：录一段复现过程

面板上现在会显示这几个数，出问题时看一眼，或者直接录下来发我：

```
遮挡处理：⚠连续解不好×37   模板已被重捕改动14.4mm   [看门狗:已松开连续性锁]
```

| 看什么 | 说明什么 |
|---|---|
| `⚠连续解不好×N` | N 一直涨 = 卡在"解不出来"，看门狗应该会在 20 帧时松锁 |
| `模板已被重捕改动 XXmm` | 重捕改过模板。如果这个数很大而画面是乱的，**说明重捕修错了地方** |
| `[看门狗:...]` | 自动恢复触发了 |
| 手背刚体那行的 `内点` | 一直 4/5 或更少 = 有点没被认回来 |

**如果这些数全都正常、画面却是乱的**，那就是我还没想到的第四条路径 —— 那种情况下
录一段发我，`Hm20Diag` 块里有 `sourcePointId[20]`，能直接看出是"标签翻了"
还是"点丢了"，这两种在画面上长得一样但成因完全不同。

复现步骤大概是：正常跑一会 → 撕下一个手背点贴到别处 → 等连线乱 →
点几下"手背复位"看能不能好。整个过程录下来。
