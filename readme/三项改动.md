## ① 批处理窗口提示：峰值 → 滑动窗口分位

### 原来那个判据为什么不好

```cpp
maxArrivalSpreadMs_ = std::max(maxArrivalSpreadMs_, arrivalSpreadMsThisCall);
const bool windowTooTight = maxArrivalSpreadMs_ > batchWindowSpin_->value() * 0.7;
```

`maxArrivalSpreadMs_` 是**开机以来的全局最大值、永不衰减**。启动那一下、
或者某次系统调度抖动打出一个孤立的 40ms，这个警告就**永远亮着**，
而实际 EMA 可能只有 2ms。

一个永远亮着的警告等于没有警告，更糟的是它会让人把真的问题也一起忽略掉。

### 改成

**最近 10 秒（240 帧）的 95 分位**。孤立尖峰被 p95 滤掉，持续偏大会被如实反映，
窗口滚动所以它能自己恢复。

### 顺带补了"太松"的方向

原来只提示"太紧"。用户为了消掉警告会一路往大调 —— 而**批处理定时器要等满窗口才出帧**，
窗口开到 50ms 就是给整条链路白加 50ms 延迟。所以两个方向都判，并给建议值：

```
相机到达偏差 2.31ms（近10秒 p95 3.80ms，批处理窗口 12ms）  ✓ 窗口合理
相机到达偏差 9.14ms（近10秒 p95 14.2ms，批处理窗口 12ms）  ⚠ 窗口太紧，会漏掉还没到的相机 → 建议 22ms
相机到达偏差 1.02ms（近10秒 p95 1.60ms，批处理窗口 40ms）  ⚠ 窗口偏大，多出来的是纯延迟 → 建议 3ms
```

判据：`太紧 = 窗口 < p95×1.4`，`太松 = 窗口 > p95×3.0+4`，`建议 = ceil(p95×1.5)+1`。

## ② 标定连拍速度 ×2

```cpp
kAutoShotIntervalMs   500 → 250      // 2 张/秒 → 4 张/秒
```

**为什么可以翻倍**：500ms 这个节拍原来是配合"严格选拔"的九宫格限量才有意义的
（存得慢一点、每张都挑过）。选拔机制去掉之后没有再压节奏的理由 ——
判糊的 `roughSharpness` 是逐帧算的，节拍快了只是尝试次数多，糊的照样被跳过。
举着板子走一遍的时间直接减半。

## ③ 严格选拔模式裁掉

它原来管两件事，两件都删了：

| | 原行为 | 现在 |
|---|---|---|
| 九宫格限量择优替换 | 每格满 4 张后，新的要比最糊的清晰 10% 才替换 | 不限量，都存 |
| "覆盖不够不能下一步" | 每机最少张数 + 重投影误差 < 0.5px 才放行 | 不设门槛 |

第二条是我判断它挡人多于帮人的地方：**重投影误差预览算得慢**，
经常出现"明明拍够了却过不去"，用户只能反复点「下一步」。
现在重投影误差**仍然照常显示**，判断交给你。

### 连带清理

删掉复选框、`strictSelectionOn_` 成员，以及因此变成孤儿的三个常量
（`kMaxShotsPerCell` / `kMinShotsPerCam` / `kMaxAcceptReprojErrPx`）。

**`boardCells_` 没删** —— 它还在支撑覆盖度显示、照片列表、撤回删除三处，
不是选拔机制专用的。头文件里那句"见 kMaxShotsPerCell"的注释改掉了，否则会指向不存在的符号。

## 验证到什么程度

这四个文件都要 Qt，**我编不了**。能做的静态核对：

| | 结果 |
|---|---|
| 括号配平（剔除字符串/注释后） | 四个文件全部 ✅ |
| `strictSelection` 残留引用 | 0 处 ✅ |
| 三个孤儿常量残留 | 0 处 ✅ |
| 新符号声明↔引用 | 头文件 3 处声明、cpp 8 处引用 ✅ |
| Qt 格式化占位符 vs `.arg` | 外层 11 vs 11 ✅（内层 2 个是提示文案里的嵌套） |

最后一条值得单独说：**Qt 的 `.arg` 数量对不上不会编译报错**，
只会在运行时静默输出错文本（多的占位符原样打出来）。所以专门数了一遍。

`#include <deque>` 已加进头文件。
