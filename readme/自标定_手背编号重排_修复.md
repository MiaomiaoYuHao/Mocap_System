# 自标定：第二条路径（手背编号重排）

上一轮我列了两条嫌疑路径，修了第一条（手性覆盖）。你说没解决，那就是第二条。
这次我把它量化验了。

---

## 一、机制

`finalizeCollect()` 里：

```cpp
const auto ord = canonicalDorsumOrder(res_.backMm, {0,1,0}, {0,0,1});
if (!identity) {
    for (int i=0;i<5;++i) tmp[i] = res_.backMm[ord[i]];   // ← 把模板重排
    res_.backMm = tmp;
}
```

模板的 5 个手背点被**按极角重排**了。

但 **Kabsch 是按标签配对的**：`tmplMm_[m]` 配观测 `markers[m]`，而 `markers` 的编号
是网络给的。重排之后模板位置 `m` 装的其实是网络标签 `ord[m]` 那个点——
**对应关系整体错开一格**。

原设计押的是"网络看到新模板会跟着重新编号"。可手背五点接近正五边形，
循环移位正是网络最分不清的情形。押不中时，没有任何东西会报错。

## 二、量化：自检为什么拦不住（`tests/test_dorsum_phase.cpp`）

```
== 编号正确 ==
   残差 0.000 mm   解出转角 0.00°

== 编号循环移位（自检阈值按典型值 5.0mm 算）==
   移1格: 残差  3.52 mm   解出转角  72.02°   ← 自检放行，但姿态已错
   移2格: 残差 39.54 mm   解出转角 179.93°   (这一格残差够大，能被拦下)
   移3格: 残差  2.37 mm   解出转角 144.01°   ← 自检放行，但姿态已错
   移4格: 残差  3.52 mm   解出转角  72.02°   ← 自检放行，但姿态已错
```

**4 种移位里 3 种能骗过自检。** 残差 2.4~3.5mm，跟正常工作时一个量级；
而腕部姿态整体转掉 72~144°。

腕部系一转，手背连线直接错；anchor 是在腕部系里存的，变换到世界系也全错，
于是手指连线跟着错。**跟你描述的症状完全一致，而且诊断数字全是绿的。**

> 阈值来源：`max(validateRmseMinMm=1.2, validateRmseK=2.5 × σ)`，
> σ 是采集期手背点抖动，真机 1~2mm 量级 → 阈值约 3~5mm。

## 三、改动

**`canonicalizeDorsum` 新增，默认 `false`** —— 不重排，`index i` 恒等于网络标签 `i`，
对应关系不会被动过。

代价：模板在不同会话之间的编号不再规范化。而**模板本来就是每次重新标的**，
这个代价基本不存在。

面板上现在会写明：`手背编号重排：本来会重排，已按默认关掉`。
**这行字就是确认信号**——如果它出现了，说明你这台机器上这条路径确实在触发，
那这次就修对了。

## 六、如果这次还是没解决

两条路径都排掉的话，剩下的最大嫌疑是**提交的手指模板**：

`rebuildNeutralMarkers()` 用群体均值合成 15 个中立位手指点，
而 `packNormalized()` 计算质心和尺度时是**按全部 20 点算的**——
这 15 个合成点虽然 `valid=0`，却会**改变那 5 个真手背点的归一化坐标**，
把网络推到训练分布之外。

标定前（无模板 / 手工模板）不存在这个问题，一提交就出现，时序也对得上。

验证方法：把 `rebuildNeutralMarkers()` 调用注释掉重试一次。
如果连线恢复正常，就是它——那我再改，思路是让归一化只用有效点，或者
干脆不提交手指模板（`INTEGRATION.md` 里本来就写了"手指标定原理上做不到"）。

**麻烦你告诉我面板上「手背编号重排」那行显示的是什么**，
这能直接判定这次修的对不对，省得我继续猜。
