# 左手 + 「右手」设置：输出到底对不对

## 一、直接回答：分四路，只有一路是错的

`isRight` 在整条链路里只进三个地方（我 grep 过，`Hm20JointAngles.hpp` 和
`HandSkeletonAssociator.hpp` 里**一次都没出现**）。所以：

| 输出 | 左手 + 右手设置 | 为什么 |
|---|---|---|
| **20 点世界坐标 / 面板连线** | ✅ **对** | 三角化测出来的，手性只影响"哪个点叫食指近节"这个标签 |
| **M3DQ 世界系四元数** | ✅ **对** | 骨轴来自实测点位；roll 由 `wristR` 推出，而 `wristR` 来自你自己左手的模板做 Kabsch |
| **M3DQ 相对父节点四元数** | ✅ **对** | 由世界系相邻段相除，同源 |
| **M3DS 的 16 维关节角** | ⚠️ **外展维符号很可能是反的** | 见下 |

**关键结论：没有任何一处会因为 `isRight=true` 去"镜像"你的输出。**
镜像只发生在 `Hm20IkRefiner` 内部，而手性不匹配时 IK 根本不生效（下面第三节）。
所以你现在拿到的是**未经镜像的真实测量**——不是"一只被翻成右手的左手"。

### 关节角为什么可能反

关节角是把分段姿态在**腕部系**里分解出来的。腕部系的 Z 轴按右手约定 = 手背外法向；
你是左手，同一套构造给出的 Z 指向**掌侧**。`Hm20JointAngles` 里没有任何手性处理，
所以**外展（展）那几维的符号大概率整体反了**，屈曲维一般不受影响（绕另一个轴）。

**30 秒就能验证**，用上一轮做的输出监视面板：

1. 勾「打印输出数据」，选「关节角(M3DS)」
2. 手指并拢 → 张开
3. 看「食 MCP展 / 中 MCP展」这几行的**输出°是往正走还是往负走**

往负走 = 符号反了。修法不用动 C++：在 Unity 端把那 5 个外展维乘 -1 即可
（`quatLocal` 那条路完全不用改，它是对的）。

## 二、你必须知道的代价

手性不匹配时，`Hm20IkRefiner` 的残差常年 10mm 以上、被残差门挡掉，
`fingerValid=false` → **IK 不覆盖 segQuat → 退回 marker→marker 两球连线**。

那条路径的实测精度是：**骨轴中位 10.2°、p90 21.6°、最大 53.3°**，
而 IK 生效时主力档是 **2.68°**。

**你用"右手设置"换来的稳定，代价是放弃了那 4 倍精度。**
做数据采集喂 IK 的话这个代价不小；只是看连线跟不跟手，那无所谓。

## 三、"左手设置反而更差"不是物理事实，是个 bug——我找到了

`Hm20IkRefiner::refine()` 原来是这么写的：

```cpp
if (!isRight_) for (int m=0;m<20;++m) obsL[m][1] = -obsL[m][1];   // 只翻了观测
const Result R = solve(obsL, observed, prevAngles_, backTemplate_);
```

而 `residuals()` 里用的是 **`anchor_[f]` 原值**。

`anchor_` / `backTemplate_` 存的是**腕部系**里的量——自标定判成左手时，那个系的 Y
已经被翻成小指侧了。而 `obsL` 在这里又被翻回"拇指侧"。**两者差一个 Y 反号**，
IK 从第一次迭代起就在拟合一个错位的目标，残差自然常年超门限。

**症状正好就是这段代码自己的注释想避免的那个**——"表现为左手 IK 永远不生效"。
镜像只做了一半。

已修：`anchor_` 和 `backTemplate_` 跟观测一起翻到同一个系里。

> **这条是代码推理，没有实测确认**（我没有真机和模型）。
> 修完之后你可以试一次「左手」设置：如果诊断栏里 IK 从"未放行/0指生效"变成
> "3~5指生效、残差 3~5mm"，就是它。**如果还是不行，就退回右手设置**——
> 你现有的工作流是可用的，不要为了这个卡住。

## 四、顺带修掉我上一轮引入的一个缺陷（重要，跟你直接相关）

上一轮加的**镜像自检**会检查"手指点是否落在模板系的 -Z 侧"。
**而你正是"左手 + 右手设置"**——这种情况下模板系的 Z 本来就指向掌侧，
手指点必然落在 +Z 侧 → **我的自检会把你的标定判为镜像并拒绝**，
反复重采直到 `attempts_` 耗尽，自标定永远标不成。

这是我的错。已改成：**只在"推断手性与设置一致"时才判镜像**。
你故意用不匹配的手性设置是合法选择，自检没资格越权拒绝。

如果你已经拿上一轮的包编译过并试过自标定，**请务必换成这一版**。

## 六、我的建议

**短期**：保持右手设置继续用。你的世界系四元数是对的，Unity 那条 `quatLocal`
路径可以直接用；只要在 Unity 端确认一下外展符号。

**中期**：试一次修完的左手设置，看 IK 能不能放行。能放行就切过去，
骨轴精度从 10.2° 到 2.68° 是数量级的差别。

**长期**：`Hm20JointAngles` 里一次都没出现 `isRight`，这意味着**关节角这一路
根本没有左手支持**。要么在里面按手性翻外展维，要么在 Unity 端翻——
后者更简单，但会把手性知识散到两个仓库里。你的下游如果只有一个 Unity 工程，
就在 Unity 翻；如果以后要接机械手，建议在 C++ 里翻。
