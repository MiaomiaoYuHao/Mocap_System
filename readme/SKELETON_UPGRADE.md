# 骨架关联链路升级说明（2026-08）

本次改动集中在 `src/estimate/`，一句话概括：**修掉了 IK 反而变差的根因，补齐了在线
闭环自标定，加了时序滤波，并让下游第一次能区分"测出来的姿态"和"猜出来的姿态"。**

所有数字都来自 `tools/skeleton_assoc/hm20_sim.py` 驱动真实 C++ 代码的离线台
（6 相机 + 时钟不同步 + 遮挡 + 光斑粘连 + 三角化，真值取自 `hand_rig.py`）。

---

## 1. 「开 IK 反而效果变差」——执行顺序错了

`Hm20SkeletonAssociator::process()` 原来的顺序是：

```
第 5 步  ik_->refine(..., out.segQuat)     ← IK 解出 16 个分段朝向
第 6 步  computeSegmentQuats(out, ...)      ← 无条件重写全部 16 个
```

IK 算出来的姿态在下一行就被整个覆盖，一个都没留下。IK 唯一的净效果变成"把网络
pos 头补的遮挡点换成 FK 摆出来的点"，而那些点比网络预测更差（网络的 pos 头是端到端
训出来的），再拿它们去连两球算骨轴，于是比不开还烂。

| 配置 | 骨轴中位 (seed1/seed2) | 遮挡点位置 |
|---|---|---|
| IK 关 | 10.80° / 13.22° | 6.40 / 5.76 mm |
| IK 开（修复前） | 11.30° / **15.53°** | 6.98 / **7.67** mm |
| IK 开（修复后） | **6.05° / 8.83°** | — |

连带修掉三处：

- **IK 在 `wristPoseValid=false` 时照样跑。** 那时 `wristR` 是单位阵或几帧前的旧值，
  转出来的"腕部系坐标"几何上无意义，IK 会认真拟合它然后输出一组自洽但完全错误的
  关节角。已加门控。
- **IK 帧和几何帧是两套 roll 约定。** IK 的 `segR` 是解剖学框架，`boneFrame()` 是
  手背法线参考系，两者 roll 可差 180°。同一根手指"这帧走 IK、下帧退回几何"时四元数
  整个翻过去——分段帧间跳变 p99 从 50° 冲到 **178.7°**。现在只从 IK 取骨轴、roll 统一
  走 `boneFrame`（绕骨轴自转在每节只有 1 个 marker 时本来就不可观测），p99 回到 48°。
- **`matToQuat` 强制 w≥0**，w 跨 0 时符号整体翻转 = 一次凭空的 180° 假运动。已加逐帧
  半球对齐。

**新增开关**（`Hm20Config`）：`ikOverrideQuat`（默认 true）、`ikFillOccluded`
（默认 **false**，因为实测 IK 补的遮挡点比网络 pos 头差：5.8mm → 7.7mm）、`ikMaxRmseMm`。

## 2. 姿态四元数到底可不可靠——现在下游能自己判断

`SkeletonFrameResult` 新增：

```cpp
std::array<SegSource, 16> segSource;   // None / Predicted / Geometry / Ik
std::array<double, 16>    segConf;
std::array<bool, 5>       fingerIkValid;
std::array<double, 5>     fingerIkRmseMm;
std::array<int, 5>        fingerObsCount;
```

**这是本次最重要的接口改动。** 原来 `segQuat` 是 16 个无差别的四元数，一根全遮挡的
手指照样输出一个看起来很正常的四元数——做动捕时它会被原样写进 c3d/bvh。现在：

- `segSource == Ik`：该指可见 marker ≥2 且残差合格，最可信
- `segSource == Geometry`：由真观测 marker 连线算出，有约 10° 贴球系统偏差
- `segSource == Predicted`：**两端点都是网络补的，只能当"大概在哪"用**
- `segSource == None`：腕部位姿都没解出来，别用

**实测可靠性结论：**

| 量 | 中位 | p90 | 说明 |
|---|---|---|---|
| 腕部姿态（`segQuat[0]`） | **1.27°** | 2.7° | 手背 5 点刚体解，最可靠；自标定和人工标定精度一致 |
| 分段骨轴（几何法） | 10.8~13.2° | 27~29° | 贴球在指节背侧、离骨轴 11~17mm 造成的系统偏差 |
| 分段骨轴（IK，参数准） | 6.0~8.8° | 18.6° | 需要个体化 anchor/骨长 |
| 绕骨轴自转（roll） | — | — | **不可观测**，每节只有 1 个 marker，输出值仅保证连续，无物理含义 |

## 3. 在线闭环自标定（`Hm20AutoCalib.hpp`，取代 `Hm20AutoTemplate.hpp`）

### 状态机

```
Idle → Warmup → Collecting → Validating → Locked → Ready
                                  ↓失败        ↑漂移检测
                              (保留模板重采集)
```

### 对操作者的要求（**不是打开就标**）

1. **整只手进视野**：手背 5 点全被认领 + 手指 ≥8 点
2. **摆稳约 0.4 秒**（连续 24 帧，帧间位移 <8mm、转角 <5°）
3. **缓慢转动手腕约 0.8 秒**（48 帧）→ 冻结手背模板
4. **自动校验 90 帧**，站不住就推翻重标（最多 6 次）
5. **反复屈伸五指** → 解出指根 anchor 和骨长，这一步最耗时（实测 300~1300 帧）

面板实时显示卡在哪一步和**本帧被拒的原因**（"手动得太快，请放慢" / "手背点没认全" /
"手背五点连线自交" / "手背点距离不稳定(可能标错)"）——只给一个不动的进度条，用户
完全无从下手。

### 三个非平凡的技术点

**(a) 刚体自检必须用标准差，不能用极差。**
48 帧、单点噪声 σ≈1.5mm 时，两两距离的极差期望就有 4~7mm。用极差判刚体等于要求
噪声为零，实测卡在 Collecting 永远不动。

**(b) 冻结后必须校验——手背 5 点近似五重对称。**
网络在还没有模板时对手背的标法不唯一，实测出现过整套**标签反向排列**：

```
GT 手背半径序列:  [28.2, 35.2, 21.8, 23.7, 34.4]
早期冻结的模板:   [34.5, 23.8, 21.9, 35.4, 28.3]   ← 正好倒过来
```

刚体自检**完全查不出来**：同一组物理点换个标法，两两距离一模一样。冻结这种模板后
Kabsch 解出的腕部系是错的，五指 anchor 平均错 44.6mm。

唯一可靠的判据是**把模板真正用起来看它自不自洽**——模板下发后网络会依据模板重新
破对称，标法不一致时 Kabsch 残差稳定偏高（实测 0.79mm vs 3.26mm）。阈值取
`max(1.2mm, 2.5σ)`，σ 是采集窗口测出的噪声底，**不是固定毫米数**（固定阈值两头不
讨好：2.2mm 就放过了上面那个错模板）。

校验失败时**保留模板继续采集**，不是清空重来——清空的话网络又回到"没模板"状态，
会再给出同一套错标法，纯粹原地打转。保留模板则构成不动点迭代，实测两三轮收敛。

**(c) 局部系必须二次对齐到解剖学系。**
自举出的系（手背质心→四指质心当 X）跟 `markerFK` 假设的系差 20~40°。系一歪零位就歪，
LM 只能拿关节角去补而限位补不动——**IK 残差 1.6mm → 10.2mm，骨轴 12.75° → 20.72°，
比不开 IK 还差**。`tryAnatomicalAlign()` 用"anchor→远节球在最伸直那帧的方向"定 +X
（定义上就是 markerFK 的零位骨轴），把系偏差压到 4.1°。

### anchor / 骨长：球面拟合 + 束调整

- **anchor 可以自动解出来。** `HandCalibration.hpp` 里"两方程三未知数做不到"说的是
  单帧；多姿势下不成立——近节球到指根关节的距离恒定，轨迹落在以 anchor 为球心的球面上，
  是标准球面拟合（跟动捕里用功能法解髋关节中心同理）。
- **束调整精修。** 内层用 `Hm20IkRefiner::solve` 逐帧解关节角（跟运行时**完全同一份
  求解器**），外层解 anchor（闭式）+ 骨长（3 参 GN）+ 全局朝向修正（3 参 GN）。
  目标函数就是 IK 运行时最小化的那个残差，所以标出来的是"让 IK 拟合得最好的参数"。
  姿势库有多样性门（重复姿势对 anchor 没有额外信息，反而让法方程病态）。
- **删掉了基于跨距的骨长闭式估计。** 它系统性偏大约 30%、五指全被钳到上界
  （食指估 52.0mm / 真值 39.2mm），而且会顺着归一化和球面拟合先验回头污染 anchor。

### IK 总闸

```cpp
bool ikUsable() const;   // frameAnatomical && anchor≥4 && bundleRmse<4mm
```

**参数没收敛时 IK 一律不挂。** 最坏情况退回几何法，不会出现比不标定还差。
实测中 `自标定+IK开` 的输出可以逐位等于 `自标定+IK关`——那就是这道闸在生效。

### 其他

- **左右手自动判定**：用手指点相对手背平面的有符号距离定出真正的手背外法向，再定手性。
  判不出来时报"未知"、沿用用户设置，**不猜**。
- **`Hm20IkRefiner` 补了左手镜像**：原来 `rotZ(外展)·rotY(屈曲)` 写死右手，左手外展
  方向整个反了，残差常年 10mm+ 被门限挡掉，表现为"左手 IK 永远不生效"。
- **漂移检测**：手背 Kabsch 残差连续超阈值 → 判定贴点移位 → 整套推倒重标。
- **中立位 20 点改用 `markerFK(q=0)` 合成**，跟训练用的 `hand_rig` 是同一个公式，
  不再用 `Hm20TemplateAdapter` 那套"骨中点、无径向偏置"的近似。

## 4. 时序滤波（`Hm20PoseFilter.hpp`）

关联网络是逐帧独立跑的，输出带逐帧独立的噪声：分段姿态帧间跳变 p99 27~35°，静止时
也有 1~3° 持续抖动。导出到 bvh/c3d 就是肉眼可见的高频颤动。

三样东西不能用同一套处理：**位置**（低通引入延迟）、**姿态**（四元数在球面上，线性
平均掉出单位球；q 和 −q 同旋转，不半球对齐会得到 180° 假运动）、**观测状态会变**
（marker 重捕时滤波器里存的是几十毫米外的预测值，直接接着滤会拖住半秒）。

方案：位置/平移用 One-Euro（截止频率随速度自适应，慢时压抖、快时不滞后）；姿态把
One-Euro 搬到 SO(3)（球面插值代替线性混合，全程留在单位四元数上）；**软死区**让静止
时真正零抖动而不产生台阶；**重捕硬复位**不留任何历史；`segSource==Predicted` 的分段
自动加强平滑。

实测（14 秒会话，5 组参数对比）：

| 预设 | 位置中位 | 位置 p90 | 高频抖动 | 分段跳变中位 | 腕跳变 |
|---|---|---|---|---|---|
| 关 | 1.32mm | 6.55 | 2.771 | 4.02° | 1.95° |
| 轻 | 1.48mm | 6.27 | 1.742 | 3.55° | 1.54° |
| **均衡（默认）** | **1.65mm** | **6.26** | **1.500** | **3.37°** | 1.42° |
| 强 | 4.51mm | 8.43 | 0.542 | 2.71° | 1.11° |

选"均衡"的理由：位置代价只有 0.33mm 中位、**p90 反而比不滤还好**，而高频抖动砍掉 46%。
"强"档抖动最小但滞后 3.4mm，不适合动捕。

## 6. 已知限制（不粉饰）

1. **免标定能拿到什么、拿不到什么。** 自标定后手背连线和腕部姿态跟人工标定基本无损
   （手背 acc 99.5%、腕部残差 1.27° vs 1.28°），但**手指 anchor/骨长的收敛不是每个
   会话都能达到 IK 门限**。实测 3 个会话里 1 个收敛（bundleRmse 3.1mm，IK 放行），
   另外 2 个没到，IK 保持关闭、退回几何法（骨轴中位 11.7~14.8°）。
2. **拇指 anchor 仍然是短板，引导式标定这条路没走通。** 详见附录 A —— 我做了完整尝试
   并如实记录了失败，没有把它包装成功能。当前拇指 anchor 误差约 9~14mm，四指 3~13mm。
3. **自标定的腕部系有约 4° 的固定偏置**（相对解剖学腕部系）。跟踪精度不受影响
   （帧间一致），做动捕时可在导出阶段一次性补掉。
4. **绕骨轴自转（roll）不可观测**，输出值只保证连续、无物理含义。要真 roll 必须每节
   贴第二个球。
5. 滤波后的 marker 位置和分段四元数是各自独立滤的，两者之间会有亚毫米级的不自洽。

## 附录 A：拇指引导式标定——尝试过程与结论（没成功）

按"四指已经能自动解到 2.6~3.8mm、拇指 14.8mm"的诊断，我尝试用引导动作专治拇指。
结论是**没达到目标**，但过程里挖出两个有价值的事实，都已固化进代码。

### A.1 找到了拇指差 4 倍的真实原因：一个被写死的逐人参数

`Hm20MarkerModel::kThumbAxialK = 0.576` 是常量，而训练语料里 `thumb_axial_k`
**逐人随机分布在 0.35~0.80**。它是拇指 CMC 外展耦合出的掌骨轴向旋前系数。

写死的代价不是"稍微不准"：外展 1 rad 时轴向偏差可达 0.22 rad，`rotX` 之后再复合
`rotY(近节屈曲)`，远节骨轴被歪掉约 11°、dp 球位置错 6mm 以上。球面拟合把这部分当
噪声吸收进球心，anchor 就被系统性拉偏。

**已修**：`thumbAxialK` 改成 `Hm20MarkerModel` 的运行时成员，`Hm20IkRefiner::setThumbAxialK()`
可设，束调整里用一维网格搜（0.30~0.90，步长 0.025）解它。这一条无论引导做不做都成立。

### A.2 「指尖相触」在标记式系统里原理上就不能当判据

第一版引导动作是"拇指指尖碰食指指尖 / 碰小指指尖"，判据是两个 marker 的欧氏距离。
实测卡在第 1 步永远过不去。原因是：**指尖真碰上时两颗球相距只有几毫米，前端会把它们
并成一个光斑**（本系统合并阈值 18mm），于是那两个 marker 不可能同时可见，判据恒不成立。

这不是仿真 artifact，真机上完全一样。**任何要求两个 marker 靠近的引导动作都是无效设计。**
已改成非接触的连续覆盖度：拇指近节球绕 anchor 的方向张角 + 远节球在腕部系里的活动范围，
只用拇指自己的点。

### A.3 为什么最终仍然没成

即使换成大幅度非接触扫动（脚本注入 6 秒、外展角在 0.05~1.10 rad 往复两轮），覆盖度
仍然到不了阈值（停在 1/3~2/3）。而我一度把「拇指覆盖度达标」当作落 anchor 的硬门，
后果是 `nAnchorFitted()` 迟迟到不了 4，`tryAnatomicalAlign` 和束调整整条链一起卡住：

| | 拇指 anchor | 四指均值 | 束调整 |
|---|---|---|---|
| 不加引导 | 9.2mm | **3.6mm** | 收敛 3.11mm，IK 放行 |
| 加引导 + 硬门 | 18.3mm | **12.2mm** | 从未运行 |

**为一根手指把另外四根拖下水，不划算。** 已把硬门去掉，覆盖度只做两件事：
① 面板提示（告诉操作者具体做什么动作）；② `thumbAxialK` 能不能拟合的**可辨识性**
判据（耦合项 = k × 外展角，外展角小的时候整项接近 0，此时任何 k 的残差都差不多，
搜出来的是噪声，必须挡）。

### A.4 我的判断

拇指要达到四指的精度，我认为**需要的不是更好的算法，而是更多的观测**：拇指掌骨上
只有 1 颗球，而 CMC 有 2~3 个自由度还带轴向耦合——**观测数少于自由度数**。
建议二选一：

- **在拇指掌骨上加贴第 2 颗球**（20 点 → 21 点）。这能让 CMC 完全可观测，是根治。
  代价是要重训模型。
- **接受拇指 ~10mm 的 anchor 误差**，在 IK 里对拇指用更强的先验约束（限位罚权重
  调高），让它至少不乱跑。

在拿到真机数据之前我不建议继续在仿真上调这个——A.3 那组数字很可能是仿真轨迹的拇指
活动范围本身就偏小，而不是算法问题。
