## 一、ROM 标定 v2（第 1~3 轮）

### 根因
`computeSegmentQuats()` 里近节骨轴有两条来源：

```cpp
dirProxUse = dirProx;                                  // = pp球 -> mp球   ← 退化
if (f != 0 && anchorsValid && out.wristPoseValid)
    dirProxUse = pp球 - anchor;                        // 正确的近节骨
```

而 `solveJointAngles()` 里算 PIP 的第二条轴恒等于 `pp球 -> mp球`。
三个条件任一不满足，两条轴重合，`PIP = acos(1) = 0`——不是不准，是结构性的零。
拇指 `f != 0` 恒假，所以**拇MCP 从来没工作过**。

这一条同时解释了「覆盖度卡在 50%」「握拳少张开满」「四元数对得上但角度不对」。

### 新增 `src/estimate/RomCalibration.hpp`
逐维采样门（拒收原因分 6 类）、用 curl 判方向、按 curl 外推补行程、
先验兜底、死维冻结中立位、补标合并。自包含零 Qt，可单独编译。

curl 用**折角**不是弦长比——弦长比是余弦型的，0~30° 只挪 0.05，
而真实开合动作大部分时间就在这一段。三段真实素材上达标率
从 3/11、2/11、2/11 提到 7/11、8/11、7/11。

### 录制格式 v7
新增块 31 `RomCalib`（逐维标定全量状态）、块 32 `JointSolve`（逐帧解算内部量：
两条骨轴、`dotProxMid`、`proxAxisSrc`、curl、逐维 `dofState`）。
新增事件码 16~19：按钮按下/结束（GUI 墙钟）+ 采样真正起止的那一帧（worker 侧），
两者分开记是因为中间隔着投递延迟。

### `tools/pcrec/pcrec.py`
支持 v7。**顺带修了个现存 bug**：`IkDbgRec` 的 C++ 是 680 字节而 py dtype 是 608，
`_take()` 对账不等就整块跳过——IK 内部那一路在之前所有分析里一直是空的。

### 新增工具
- `tools/pcrec/rom_report.py`——v7 录制的五节定位报告
- `tools/pcrec/rom_offline_dump.py` + `rom_offline_run.cpp`——**不用重录**，
  拿现有 v5/v6 文件就能跑真正的 C++ 标定器

## 二、关联器按职责重切（第 4 轮）

原来的 `Hm20SkeletonAssociator_impl{1,2,3}.ipp` 是**按行号**切的
（1382–2405 / 2406–3467 / 3468–4497），文件名说不出里面装什么。

统计依据：92 个数据成员里 **80 个只被 1~3 个函数碰**——这个类不是一团乱麻，
是几台互不相干的状态机挤在一起。所以改成按职责切：

```
Hm20Assoc_types   29    api    407   process 623   chain  966
Hm20Assoc_dorsum 461    geom   286   segrot  260   thumb  207
```

入口 `HandSkeletonAssociator.hpp` 顶部带导航表。每个分片开头**显式写死**
access 说明符（原来 impl2 开头两个函数是 public，只因为 impl1 碰巧以
`public:` 结尾）。每组的数据成员排在自己的函数前面。

内容守恒：丢失 0 行，非注释新增 0 行（逐行多重集比对）。

## 三、测试套变成真门禁（第 5 轮）

原来 58 个测试里 10 个长期红着。逐个查完：

**7 个根本不是测试**——是需要 `.pcrec` 的分析探针，`main` 里直接 `argv[1]`
不查 `argc`，无参运行段错误。而段错误在汇总里跟断言失败长得一模一样。
→ 移到 `tools/probes/`（**文件名没改**），加入参守卫。

**1 个是常量存了三份**——`jointLimits` 同时存在于 C++ `HandModel.hpp`、
Python `hand_model.py`、训练 rig `pose_prior.py`，代码对齐了 rig，测试还在
断言旧的 Python 表。→ 改成查**性质**（上限>下限、屈曲维允许反张、
四指外展对称），不再抄第四份数值。

**结果：48 通过/10 红 → 50 通过/2 红。**

### 【修正】CMakeLists 曾被我改坏过一次

目标重名、源文件路径不存在、`add_test` 指向不存在的目标、测试名重名。

## 五、IWYU 清理 + pcrec 去重（最后一轮）

### 修了一个真 bug：`pcrec_report.py` 加载到旧库

`tools/hand_diag/pcrec_report.py` 原来第 7 行是裸的 `from pcrec import load, calib`。
Python 会把脚本自身所在目录放在 `sys.path[0]`，于是它加载到的是
`tools/hand_diag/pcrec.py`——那份停在 v3，不认识块 30/31/32，还带着
IkDbg 608/680 的尺寸错位。

后果不是报错，是【静默少几块】：报告照常输出，只是 IK 内部和 ROM 那几节空着，
看起来像"这次没录到"。隔壁 `pcrec_diagnose.py` 和 `gen_v4_selftest.py`
都写了指向 `../pcrec` 的三行，就它漏了。

已补上，并删除 `tools/hand_diag/pcrec.py`。四个使用者验证过都指向 v7 那份。

### IWYU：8 个头 include 了它们用不到的类

estimate 目录下 7 个头【一次都没提到 `Hm20SkeletonAssociator`】，却 include
完整的 `HandSkeletonAssociator.hpp`（闭包 5776 行）。它们要的只是
`SkeletonFrameResult` / `Hm20Config` / `IHm20InferenceBackend` 这些类型——
那些在 `Hm20AssocContract.hpp`（闭包 1557 行）里。已全部改过来。

`Hm20IkRefiner.hpp` 那处原来写的是不带 `estimate/` 前缀的
`#include "HandSkeletonAssociator.hpp"`，靠"同目录"解析——批量检查 include
时最容易漏掉这种。

每个改完都单独 `-fsyntax-only` 验证过。

### 【重要】这一步买不到编译时间

实测收益是 **0**。原因：`SkeletonAssocWorker.hpp` 真的需要那个类（3 处用到），
而 UI 的 dialog 头 include 了 `SkeletonAssocWorker.hpp`，所以关联器还是
经这条路到了每个 UI 编译单元。

三条路都量过，都是 0：

| 方案 | 实测 |
|---|---|
| dialog 头去掉 `SkeletonAssocWorker.hpp` | 做不到——`SkeletonAssocDiag` 是值成员 |
| 把 `SkeletonAssocDiag` 抽成独立头 | 只省 2241 行，它自己依赖 7 个 estimate 类型 |
| 7 个头改 include contract | 0——类经别处仍然到达 |

**估计栈是一团紧耦合的簇**，整个 estimate 目录只有 4 个真正的叶子
（RadiusRefine 95 / OrtRuntimeLoader 112 / Hm20SegRot 174 / Hm20AssocBase 352）。

唯一剩下的路是 dialog 改持 `unique_ptr<SkeletonAssocDiag>`，代价是
26 处 `lastDiagSnapshot_` + 304 处 `diag.` 使用点，全在 Qt 文件里。
**没有编译器在旁边不建议做。**

所以这一步保留的理由是【正确性和可复用性】，不是编译速度：
那 7 个头现在不再假装依赖一个它们用不到的类。

## 六、ROM 方向稳定性 v3：弯曲→增加，不再逐指瞎猜

### 真机根因

1. 四指 PIP 的 `hingeSigned` 在同样握拳的不同循环里会翻号。
   小指最明显：有的循环 q 随弯曲增大，有的循环随弯曲减小；单看某一维的
   中位差无法稳定判方向。
2. 拇CMC屈不能复用拇指整体 curl。拇指 curl 主要反映 MCP/IP，
   在最新录制里拇CMC原始角与它的秩相关只有 -0.071；但同一条录制里
   拇CMC原始角与“四指共同 curl”的秩相关是 -0.674。

### 改动

- `Hm20JointAngles.hpp`
  - 四指 PIP 统一取 `abs(pip)`，直接输出“弯曲量”：弯曲增加、张开减小。
    PIP 目标行程是 `[0,1.92]`，本来就不表示反屈；稳定趋势优先。
  - `JointSolveDebug` 增加 3 组逐维方向参考：
    本指 curl、四指共同 curl、拇CMC屈专用参考（拇指尖→食指MCP距离）。
- `RomCalibration.hpp`
  - `FrameObs` 支持 3 组方向参考。
  - `resolveSigns()` 逐维遍历所有候选，选“样本够、跨度够、|秩相关|最大”的
    那条定方向；相关不足时才退回两端中位差。
  - `humanReport()` 摘要增加“方向不明 N”，不再把方向未知藏进“失效 0”。
- `SkeletonAssocWorker.hpp`
  - 实时把 `signRef / signRefValid` 送进 ROM；完成事件也显示“方向不明 N”。
- `rom_offline_dump.py` / `rom_offline_run.cpp`
  - 离线格式升级为 `OBS2`，复现多候选方向参考和 PIP 弯曲量。
- 新增 `rom_trend_check.py`
  - 对真实录制的 ROM 后每一次握拳，逐个屈曲维断言
    `输出(握拳) > 输出(张开)`。
