# 相机标定 / 3D 点云追踪 —— 全维度极限压力测试报告与端到端优化方案

测试对象：多相机光学动捕系统（ChArUco/挥球标定 + 多视图仲裁点云追踪）
测试规模：**1063 组追踪配置 + 124 组标定配置**，全部驱动生产代码本身，非重写算法
真值基准：所有误差均为**相对已知真值的绝对误差**，而非自洽的重投影误差

---

## 0. 结论摘要（先看这一节）

| # | 结论 | 量化证据 |
|---|---|---|
| 1 | **存在一个会导致系统完全静默失效的 P0 缺陷** | 检测精度优于 0.18px 时，输出点数 = **0** |
| 2 | **重投影误差不是有效的标定质量判据** | corr(重投影, 真实几何误差) = **0.564**，只解释 32% 方差 |
| 3 | **标定实际输出精度远低于追踪模块的需求** | 主点：需要 ≤0.5px，实际产出 **3.8px**（超标 7.6×） |
| 4 | **时间不同步与目标速度存在极强耦合** | 耦合放大系数 **49.9×** |
| 5 | **真实标定输出喂进追踪管线，召回率仅 18%** | 而完美标定下是 99.3% |

**一句话总结：追踪模块 0.55mm 的基线精度是一个假象——它只在"完美标定"下成立。真正的系统瓶颈在标定模块的绝对精度，而现有质量判据（重投影误差）看不见这个问题。**

## 1. 测试台建设

### 1.1 追踪压测台（C++）

直接驱动生产代码：`clusterMultiView` / `TriangulationRefine` / `TemporalTracker` / `IekfPointTracker` / `Triangulation.cpp`。
通过一层 Qt shim 让 `Triangulation.cpp` 脱离 Qt 独立编译，因此测的是**真实代码路径**，不是复刻版。

仿真侧完整复现真实工况干扰源，全部连续可调：

| 干扰源 | 建模方式 |
|---|---|
| 高斯噪声 | 像素级，σ 连续可调 |
| 脉冲噪声 | 按概率注入大幅跳点（二值化闪烁/传输误码） |
| 离群点 | 观测整体被替换为随机位置（错检/串扰） |
| 遮挡 | **突发式**状态机（一旦遮挡持续 N 帧），非独立同分布 |
| 反光 | 真实点附近生成镜面鬼影 |
| 运动模糊 | 沿像面速度方向的**系统性质心滞后** + 方差抬升 |
| 景深畸变 | σ 随 \|深度−合焦面\|² 增长 |
| 时序不同步 | 每台相机独立时间戳偏移，在偏移时刻重新采样物体位姿 |
| 物体形变 | 标记点相对刚体模型的低频摆动 |
| 环境杂点 | 视场内随机分布干扰亮斑 |
| 光照剧变 | 影响检测丢失率 + 质心方差，奇偶相机分别模拟强光/弱光 |
| **标定误差注入** | 外参旋转/平移、内参焦距/主点/畸变，独立可调 |

指标：3D RMSE / P50 / P95 / Max、召回率、幽灵率、ID 跳变数、轨迹抖动（三阶差分 RMS）、漂移、平均支持视角数、单帧耗时。

### 1.2 标定压测台（Python + OpenCV）

**不是"在理想角点上加噪声"。** 真渲染 ChArUco 图像：

```
板面纹理 → 透视投影(单应) → 镜头畸变(逆映射重采样) → 景深失焦
        → 方向性运动模糊 → 空间光照梯度/暗角/伽马/闪烁
        → 镜面高光 → 遮挡块 → 环境杂点 → 高斯+椒盐噪声 → JPEG 压缩伪影
```

再喂给**你原本那个** `CharucoDetector`（含 CLAHE 回退逻辑）、`cv2.calibrateCamera`（含 MAD 稳健剔除）、`spanning_tree_poses`、`board_pose_graph_ba`。
检测失败率、亚像素偏差、离群角点全部由渲染管线自然产生。

### 1.3 建台过程中的两个物理错误（反证"理想化仿真会骗人"）

| 错误 | 症状 | 教训 |
|---|---|---|
| look-at 矩阵左手系（det = −1） | 板子被镜像，ArUco 永远解码不出 | **你的 `CameraExtrinsics::fromJson` 正交性校验实测能拦住这类脏数据，这段防御写得对** |
| 背面剔除方向写反 | 渲染出"背面也能标定"的假数据，solvePnP 返回翻转解（126° 误差） | OpenCV 板系 X右/Y下 ⇒ Z=X×Y **背离**观察者 |

## 2. 🔴 P0 缺陷：`MultiViewCluster.hpp` — 系统在"输入太好"时完全失效

### 2.1 现象

| 检测噪声 σ | 召回率 | 输出点数 | RMSE |
|---|---|---|---|
| **0 px** | **0.000** | **0** | — |
| **0.1 px** | **0.000** | **0** | — |
| 0.25 px | 0.993 | 2384 | 0.48 mm |
| 1.2 px | 0.993 | 2384 | 2.34 mm |

### 2.2 根因

```cpp
inline bool invert2x2(double xx, double xy, double yy, double out[2][2]) {
    const double det = xx*yy - xy*xy;
    if (std::abs(det) < 1e-15) return false;   // ← 绝对阈值，量纲是归一化坐标的四次方
```

输入是**归一化坐标系**下的协方差，`var = (σ_px/f)²`，`det ≈ var²`：

| σ | var | det | 结果 |
|---|---|---|---|
| 0.05 px | 3.1e-09 | 9.5e-18 | **被丢弃** |
| 0.10 px | 1.2e-08 | 1.5e-16 | **被丢弃** |
| 0.18 px | 4.0e-08 | 1.6e-15 | 临界 |
| 0.30 px | 1.1e-07 | 1.2e-14 | 通过（仅 12 倍余量） |

调用点：`if (!invert2x2(...)) continue;` —— 观测被**静默跳过**，候选凑不够 support，全部被丢弃，**无任何报错**。

### 2.3 危险性

1. **症状反直觉**：优化检测器、换更好的镜头、把标记球擦干净 → 系统反而彻底不工作
2. **随焦距漂移**：等效 σ 门限 ∝ 1/f²。f=900 时是 0.18px，f=1800 时是 0.36px → 表现为"A 相机能跑、B 相机死机"
3. **仅在马氏路径触发**：不传协方差时走欧氏退化分支完全正常 → "接了检测层协方差之后系统反而不出点了"

### 2.4 修复（已实施）

改为**无量纲的正定性判据**：`xx>0 && yy>0 && ρ² < 1−1e-9`。与单位、焦距、检测质量均无关，只有真正病态才拒。

**验证：**

| σ | 修复前 recall | 修复后 recall |
|---|---|---|
| 0 | 0.0000 | 0.9896 |
| 0.05 | 0.0000 | 0.9929 |
| 0.1 | 0.0000 | 0.9933 |

## 3. 🟠 标定模块：重投影误差是**不可信**的质量判据

### 3.1 统计证据（88 组有效标定）

```
corr(重投影误差, 真实几何误差) = 0.564   ← 只解释 32% 的方差
corr(主点误差,   真实几何误差) = 0.883   ← 主点几乎单独决定标定质量
真实几何误差：中位数 2.63px，90分位 11.72px，最大 50.86px
```

**而主点恰恰是重投影误差最不敏感的参数。**

### 3.2 反例（最能说明问题的两组）

| 工况 | 重投影误差 | 真实几何误差 | 说明 |
|---|---|---|---|
| 板子近乎正对相机 (tilt=0.15) | **0.2245 px**（正常） | **50.86 px** | 焦距误差 **9.44%**，重投影完全不报警 |
| 板子被遮挡 25% | **0.1481 px**（全场最低！） | 2.98 px | 约束变少 → 拟合更"自洽"但更不准 |
| 多角度倾斜 (tilt=1.0) | 0.2116 px | 12.60 px | 焦距误差 0.033% |

**tilt=0.15 与 tilt=1.0 的重投影误差差异仅 6%（0.2245 vs 0.2116），但真实焦距误差相差 286 倍。**
这是平面标定的经典退化构型（焦距与距离无法分离），而现有流程对此**零告警**。

### 3.3 修复（已实施）

在 `calib_intrinsics()` 末尾增加两项真实判据：

**判据①：位姿多样性（板法线张角）** — 拦截平面标定退化
```
< 12° → [严重]   12~20° → [警告]   > 20° → OK
```

**判据②：参数不确定度** — 用 `cv2.calibrateCameraExtended` 输出主点标准差，并直接换算成下游追踪需要的 `calibSigmaNorm`
```
> 2.0px → [严重]（下游召回率 0.99→0.13）
> 1.0px → [警告]（下游召回率约 0.80）
```

**验证：**

| 工况 | 旧判据(重投影) | 新判据① | 新判据② | 真值 |
|---|---|---|---|---|
| 退化 | 0.2245 px（正常） | **3.3° 严重** ✓ | **9.32px 严重** ✓ | 几何误差 50.86px |
| 良好 | 0.2116 px（正常） | 22.5° OK ✓ | 3.68px 严重 ✓ | 几何误差 12.60px |

两项新判据均正确判别，旧判据完全失明。

```

```

**这是整个测试最重要的一个数字。**

### 5.3 修复效果：给门控加入标定偏差项

**根因分析**：检测层协方差只描述"检测噪声"（零均值、逐帧独立、多帧平均会抵消），不含"标定偏差"（**系统性**、全画幅全时段恒定、不会因多看几帧变小）。两者统计性质完全不同，但现有门控只建模了前者，于是标定偏差把整个噪声预算吃光。

**修复**：`clusterMultiView` 新增 `calibSigmaNorm` 参数，按方差可加性并入马氏门控。

| 主点误差 | 修复前 recall/RMSE | 修复后(cs=0.002) | 提升 |
|---|---|---|---|
| 0 | 0.9933 / 0.58 mm | 0.9933 / 0.56 mm | **无代价** |
| 0.5 px | 0.9928 / 2.24 mm | 0.9933 / 1.16 mm | RMSE −48% |
| **1 px** | 0.7967 / 21.3 mm | **0.9892 / 2.56 mm** | RMSE **−88%** |
| **2 px** | 0.1288 / 48.1 mm | **0.9915 / 5.08 mm** | 召回 **+670%** |
| 4 px | 0.0126 / 31.7 mm | 0.6418 / 31.3 mm | 召回 **51×** |

| 外参平移 | 修复前 | 修复后(cs=0.002) |
|---|---|---|
| 2 mm | 0.8839 / 13.7 mm | **0.9933 / 2.31 mm** |
| 5 mm | 0.0438 / 28.8 mm | **0.9871 / 8.30 mm**（召回 22×） |
| 10 mm | 0.0167 / 52.5 mm | 0.3701 / 41.6 mm |

**关键：标定完美时零代价（0.9933/0.56 前后一致），高噪声段也完全无影响。这不是"把门控无脑放宽"——它只放宽到与标定质量相称的程度。**

推荐默认值 **`calibSigmaNorm = 0.002`**（f=900 时 ≈1.8px）。0.004 无额外收益也无害；0.001 在大误差下不足。

### 5.4 多干扰叠加的耦合放大

| 干扰组合 | 耦合放大系数 | 判定 |
|---|---|---|
| **时序不同步 × 目标速度** | **49.9×** | 🔴 强超线性 |
| 反光 × 环境杂点 | 3.02× | 🟠 超线性 |
| 外参旋转 × 遮挡 | 1.06× | 近似可加 |
| 高斯噪声 × 遮挡 | 0.80~0.94× | 次可加（饱和） |
| 高斯噪声 × 外参旋转 | 0.88~0.99× | 次可加 |

**时序不同步 × 速度是唯一的强耦合项：**

| desync\speed | 300 mm/s | 700 | 1400 | 2500 |
|---|---|---|---|---|
| 0 ms | 0.54 mm | 0.58 | 0.58 | 3.28 |
| 2 ms | 0.64 | 0.94 | 5.46 | 15.30 |
| **6 ms** | 1.04 | 7.37 | **27.44** | **46.45** |
| 14 ms | 11.39 | 26.69 | 47.34 | 48.54 |

物理机制：误差 ≈ desync × speed（本质是乘性），且不同相机在不同时刻采样导致视线在空间上根本不相交，三角化本身退化。

**⚠️ 直接影响标定模块：`solve_calibration.py` 的 `TOL_NS = 12ms` 跨相机配对窗口。挥球标定时球速通常 1000~2000 mm/s，12ms 对应 12~24mm 的配对位置误差——用一把比目标精度还粗的尺子在量毫米级的外参。已收紧至 2ms（可用 `MOCAP_SYNC_TOL_NS` 环境变量覆盖）。**

## 6. 三层优化方案

### ① 即时可调参数（零代码风险，今天就能生效）

| 参数 | 位置 | 现值 | 建议值 | 依据 |
|---|---|---|---|---|
| `calibSigmaNorm` | `clusterMultiView` | 0（新增） | **0.002** | §5.3，召回 +670% |
| `TOL_NS` | `solve_calibration.py` | 12 ms | **2 ms** | §5.4，耦合 49.9× |
| 标定视图数 | 采集规程 | — | **≥15，且倾斜 30~45°** | §3.2，退化构型 |
| 相机基线 | 机位规程 | — | **≤1000mm** | §4.3，1900mm 时误差 67mm |
| 安装高度 | 机位规程 | — | **≤500mm** | §4.3，1400mm 时误差 90mm |
| 标定轮次 | 采集规程 | — | **≥9** | §4.3，3 轮时误差翻倍 |
| `min_hits` | 追踪器 | 3 | 视场景 1~3 | 召回/幽灵权衡 |

**不建议动的参数**（实测无效或已最优）：
- `min_ray_angle_deg` — 全区间无差异（本机位构型下视线夹角本就充足）
- `ambiguity_margin` — 效果微弱且偏负
- `lm_huber` — 全区间无差异
- `max_missed` — ≥12 后饱和

### ② 算法 / 预处理 / 约束改进（已实施 3 项，另建议 3 项）

**已实施：**

1. ✅ **`invert2x2` 改为无量纲正定性判据**（`MultiViewCluster.hpp`）— 修复 P0 静默失效
2. ✅ **门控加入标定偏差项 `calibSigmaNorm`**（`MultiViewCluster.hpp`）— 标定容忍度提升 4~50×
3. ✅ **标定质量双判据**（`solve_calibration.py`）— 位姿多样性 + 参数不确定度，替代不可靠的重投影误差

**建议后续：**

4. **主点约束/固定**。主点是唯一"需求-供给"缺口达 7.6× 的参数，且几乎单独决定几何误差（corr=0.883）。工业相机的主点通常非常接近画幅中心，建议提供 `CALIB_FIX_PRINCIPAL_POINT` 选项——用先验换掉一个约束极弱的自由度，通常比"标定出一个错的主点"更准。
2. **遮挡是追踪的最大短板**（0.10 即衰减、0.30 即失效），且突发式遮挡比独立同分布遮挡破坏力大得多。建议引入刚体/骨架先验做遮挡期约束（项目已有 `HandModel`/`FingerChainSegmentation`，可复用）。
6. **时间戳插值补偿**。既然误差 ≈ desync × speed，在已知各相机时间戳的前提下，把观测按速度外推到公共时刻即可把 49.9× 的耦合几乎完全消除，成本远低于硬件同步改造。

### ③ 架构层面中长期方向

1. **建立"标定质量 → 追踪需求"的契约（最高优先级）**
   当前两个模块各自"自认为合格"，但没有任何机制保证标定输出满足追踪输入要求。建议：
   - 标定产物 `calibration.json` 中**持久化不确定度**（主点 σ、外参 σ），不只存点估计
   - 追踪启动时读取该不确定度自动设置 `calibSigmaNorm`，并在超出可用范围时**明确拒绝启动**，而不是静默降级到 18% 召回

2. **在线自标定 / 残差偏差估计**
   标定偏差是系统性的、可观测的（表现为持续同号的重投影残差）。运行时用长时间累积的残差反估各相机的主点/外参偏置并补偿，可从根本上关闭 §5.2 的供需缺口。项目已有 `HandRigidAutoCalib` / `HandAutoCalibPipeline`，架构上具备扩展基础。

3. **端到端质量指标替代分模块自洽指标**
   本次测试的核心方法论结论：**任何模块的自洽指标（重投影误差、三角化残差）都不能代表端到端精度。** 建议在 CI 中固化一套"真值已知"的合成回归集，每次改动直接跑端到端绝对误差。本次交付的两套压测台可直接充当该回归集。

4. **区分"理论可行边界"与"工程稳定可用区间"**

| 项目 | 理论可行边界 | 工程稳定可用区间 |
|---|---|---|
| 检测噪声 | σ ≤ 5 px（召回 71%） | **σ ≤ 2.5 px** |
| 遮挡率 | ≤ 0.45（召回 20%） | **≤ 0.10** |
| 时序不同步 | ≤ 16 ms | **≤ 2 ms @1400mm/s** |
| 主点误差 | ≤ 2 px（修复后） | **≤ 1 px** |
| 外参平移 | ≤ 10 mm（修复后） | **≤ 5 mm** |
| 相机基线 | ≤ 1900 mm | **≤ 1000 mm** |

## 9. 未完成 / 已知局限

1. **标定扫参完成 124/约150 组**（单核环境，ChArUco 检测器单次约 0.4s）。缺 F 组"内参质量 → 外参"传导链路的完整数据，但该链路的两端已分别量化。
2. **每组标定配置仅 1 个随机种子**。`gauss=5` 出现 geom=34.6px 的离群值（相邻档位均为 2~6px），提示**标定存在重尾失效分布**——偶发产出灾难性错误结果。这本身是重要发现（更加说明需要判据②的不确定度估计），但需要多种子重复才能量化其发生概率。
3. **T5 管线参数扫描的基线设置过严**（含 `intr_c_px=4`，该项单独即可使召回率降至 0.01），导致多数参数差异被淹没在饱和区。已用修复后的现实工况重跑关键参数，但完整的参数联合寻优仍待补充。
4. **零噪声下 RMSE 反而是 5.89mm** 的异常未完全定位。怀疑是零噪声导致 Sampson 距离出现精确并列、匹配器任意打破平局所致。属合成数据的病态边界（真实检测器不会有 0 噪声），优先级低，但提示匹配器的并列处理值得复核。
