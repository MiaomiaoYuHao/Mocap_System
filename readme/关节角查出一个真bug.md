## bug：PIP 用错了骨轴

贴球几何是这样的（`HandSkeletonAssociator.hpp` 里早有注释记着）：

```
球心贴在每节指骨的【远端】附近，于是：
  anchor -> pp球  = 近节骨    （赋给 sProx）
  pp球   -> mp球  = 中节骨    ← 【没有被赋给任何一段】
  mp球   -> dp球  = 远节骨    （赋给 sDist）
```

而 `sMid` 在 `midDirMode=0`（默认）时是 `pp->dp`，**跨了中节+远节两节骨**。

`solveJointAngles` 拿 `sProx` 和 `sMid` 求夹角 —— 算出来是"折线的转折角"，
不是 PIP 关节角。实测压缩比**恒定在 0.42**：

```
真实PIP    算出
   10       4.2
   40      16.6
  100      39.0
```

修法：直接取 `pp球->mp球` 这个向量（markers 里现成就有），
转到腕部系再跟近节骨求夹角。

验证（合成骨架按真实贴球几何造）：

```
设定 PIP=40 -> 读出 40.0
设定 PIP=30 -> 读出 30.0
设定 PIP=16 -> 读出 14.7
```

## 另外两件（不是 bug，但要知道）

**① ROM 没标定，常量零位偏置一个都没吸收。**

你截图里 `解算°` 和 `输出°` 十六行完全相同 —— `RomMapper::apply` 在
`rom.ready()` 为假时只钳位、不映射。

所以外展那条递减梯度（食 23.0 → 中 12.3 → 无 8.0 → 小 −1.3）原样透传了。
那是掌骨扇形张开的固有偏置，ROM 标定本来就是用来吸收它的。

**② 握拳时四指全部无效，中节+远节全是"预测"。**

图3：`逐指有效 拇✓ 食✗ 中✗ 无✗ 小✗`，来源列 近节=几何、中节/远节=预测。

握拳时中远节球被手掌挡住是物理必然。也就是说**握拳姿态下 15 个手指球里有 8 个
是估计值** —— 这正是"最大跳变 23mm 消不掉"的来源。

## 我在这一轮里连续犯的错

查这个 bug 花了五次迭代，前四次都是**测试写错**而不是代码错：

1. 没设 `segSource` → `measured()` 不过，整根手指被 continue，两路都返回 0
2. 三个球共线 → `dirProx` 和 `dirMid` 平行，PIP 恒为 0
3. 远节又多弯 20° → 测的语义跟被测对象对不上
4. **没设 anchor** → `sProx` 退回 `pp->mp`，那就是中节骨本身，夹角恒为 0

每次都产出"全是 0"或"跟设定值无关"的表，**看着像代码有问题**。
真正的问题是我造的合成骨架跟真实贴球几何不一致 ——
直到去读 `dirProxUse` 那段注释才搞清楚。

中途我还改错过一版（用 `sDist`，那是远节骨，算出来是 PIP+DIP），已撤回。
