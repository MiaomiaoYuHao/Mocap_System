## 我之前漏掉的取舍

上一轮定 `alpha=0.4` 时**只看了跳变**。加上"离真值多远"这个维度之后：

```
alpha=1.00（关）| 中位 6.74  p75  9.22  p90 15.34
alpha=0.80      | 中位 6.41  p75  9.51  p90 15.26   <- 现在取这个
alpha=0.40      | 中位 5.48  p75 11.42  p90 18.59   <- p90 差 21%
```

**0.4 把 p90 做差了 21%。** 平滑有滞后，遮挡期手动得快时预测跟不上 ——
输出更平但更不准，那不是改进，是把问题换了个形式。

0.80 是拐点：中位比不平滑还略好，p90 持平，同时把恢复跳变从 7.14 压到 0.83。
**三项都不亏。**

测试门限也跟着重定（转遮挡从 <2.5 放到 <4.0），理由写在测试里 ——
**不能为了让测试变绿去迁就一个更差的参数**。

## 骨长回正：验证是精确的

```
回正之后，实际骨长与标定值的偏差:
  全部       中位 0.000 mm  (n=2645)
  父点可见   中位 0.000 mm  (n=1773)
  父点也遮挡 中位 0.000 mm  (n=872)
```

沿链两档都是 0.000mm。而且单独看它是**纯收益**（中位/p75/p90 全降）。

顺带改了骨长估计：**EMA 换成滑动窗口中位数**。
真机三点全可见时的实测骨长本身就在飘（食指 p5~p95 达 38.4%），
EMA 会跟着噪声走，学出来的"标定值"不稳。中位数对离群值免疫。

## 三次统计口径错误（都是我的）

1. **五根手指骨长混在一起统计** —— 量出来的"离散"大部分是指间差异
   （mdLen 实测 20.4~29.0mm），不是抖动
2. **测试只驱动了 smoothPredicted，没驱动 snapToBoneLength** ——
   量到的骨长是没回正过的
3. **拿"骨长离散度"当判据** —— 回正后偏差恒为 0.000mm，那个离散度
   测的其实是标定值随时间的缓慢更新，跟算法质量无关

最后换成"跟恢复瞬间的实测真值比"才是有意义的判据。
