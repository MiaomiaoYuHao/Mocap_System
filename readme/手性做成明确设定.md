# 手性：改成一次性明确设定

## 先说一个关键事实：两路自动判定本来就【没有生效】

查过了：

- 自标定那一路 `applyHandedness` **默认就是 false**，只报告不生效
- 模型那一路 `aiHandIsRight` **只用于显示**，没有任何地方拿它改模板

**真正生效的一直是面板上「右手」那个勾。** 所以你看到的"错判"是显示层乱跳，
下游用的还是你的设置。

---

## 修了一个真 bug：模型手性投票

```cpp
if (r == handVote_) ++handVoteN_;
else { handVote_ = r; handVoteN_ = 1; }   // 一帧不一致就清零重来
aiHandIsRight_ = r;                        // 而显示用的是【单帧】判定
```

指尖一遮挡、模型翻一下，计数归零，锁定永远建不起来；而显示是逐帧的。
**这就是"只要有一个点进入预测状态就马上错判"。**

改成置信度加权多数 + 锁定：

```
遮挡段错判率   31.7% → 0.7%
真换手跟上     慢 8 帧（0.33 秒），可接受
```

## 改成一次性设定

- **首次打开弹一次**确认左/右手，写进 `handIsRightConfirmed`，之后不再问
- **状态栏常驻显示生效手性**（原来藏在勾选框里，设反了画面上看不出来）
- **AI 判断标成「仅供参考」**；跟设定不一致时提示"请核对面板勾选"，
  而不是悄悄改过去

## 为什么不做自动判定：这是数学结论，不是实现问题

我试了**四种**纯几何构造，全部失败：

| 构造 | 结果 |
|---|---|
| 手背五边形有符号面积 | 镜像后不变号 |
| 四指近节排列 × 手指方向 | 不变号 |
| 弯折方向 + `wristR` 同向化 | 两段同一只手算出**相反**符号 |
| 弯折方向 + 首帧法向同向化 | 两段一致了，但镜像也不变号 |

根因是同一个：

```
镜像 M（det = -1）
从手上点算的法向：  n' = -M·n
从手上点算的叉积：  (X×V)' = -M(X×V)
乘积：(X×V)'·n' = (X×V)·n        恒不变号
```

**只要法向也从手上的点算，两个负号必然抵消。**
一只左手和它的镜像在几何上完全等价 —— 手性不是形状的内蕴属性。

第三次尝试时数据"看起来对了"（两段一致），但那是因为 `wristR` 由模板求解、
**模板手性一变它就翻** —— 等于把结论建在待判定的量上。
第四次改用首帧法向，又踩回同一个坑。

## 顺带查清的：握拳时为什么信息不足

```
握紧时可见段的 PIP 夹角  中位仅 12°
```

握紧时中远节球被手掌挡住，**剩下看得见的那一段恰恰是弯折最小的**。
所以任何依赖当前弯折的判据在握拳时必然失效，不是判据设计问题。

按弯折角加权 + 门限 + 锁定的方案（`accumulateGeoHandedness`）**代码保留但不接入**：
它在非镜像场景下能稳定锁定（两段素材 11~32 帧内锁定、之后 100% 一致），
以后如果加了不对称贴球方案可以直接用。
