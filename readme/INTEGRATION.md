# hm20 接入指南（本文件取代旧的 CPP_FIXES.md）

## 0. 先纠正两条我之前说错的

**① `tmpl` 单位——我在旧 CPP_FIXES.md 里写反了。**

正确的是：**ONNX 输入用归一化坐标**（你原来的注释是对的），定义见 `synth.py`：

```
c = 20点质心;  s = 20点到c的平均距离;  f = (p-c)/s
tmpl[0..59] = f 展平,  tmpl[60] = 手性(+1右/-1左)
```

Kabsch **另外**需要一份毫米副本（它要跟世界系观测做无缩放刚体拟合）。
这是两份不同的数据，不能共用一个数组。

顺带：`net.py` v7 已把模板尺度下界改成相对量，所以 v7 之后模型对 `tmpl`
单位不敏感，两种都能跑。但 **v6 模型仍然敏感，必须发归一化**。

**② `tmpl_valid` 必须发 (1,20)，不是 (1,1)。**

如果你看到 `tmpl_valid.view(B, 1)` 这行 —— 那是 `tools/hm20_bench/net.py`，
抬头写着 **v5**，是早期遗留文件，不是训出 `hm20_v6` 的那份。v6 用的是广播：

```python
_t = tmpl_valid.reshape(B, -1)
tvm = (zeros(B, 20) + _t).unsqueeze(-1)     # (B,1) 和 (B,20) 都吃
```

导出图两种形状都验过通。但**语义上必须发 (1,20)**：

```cpp
std::array<float,20> tv{};
for (int m = 0; m < 5; ++m) tv[m] = 1.0f;   // 手背5点：HandTemplateStore 有
// 手指 15 个保持 0：HandCalibration.hpp 里写明做不到自动标定
```

发 `(1,1)=1.0` 等于告诉模型"20 个中立位我全知道"，而手指那 15 个是垃圾值。
实测三档准确率：

```
全20点模板 93.80%    仅手背5点 92.78%    无模板 87.47%
```

发 (1,1) 但手指是垃圾 → 比 87.47% 还差，且不报错。

## 1. 上哪个模型：v6

```
                  v6      v7     对姿态的影响
漏检             4.96%   0.27%   良性(FK补出来)
手背<->手背       0.49%   1.43%   腕部跳 74°
手指判别          3.74%   4.06%   手指姿态坏
──────────────────────────────
有害合计          5.02%   6.82%
腕部相位翻转     6.8秒/次  2.3秒/次
```

v7 标签准确率更高（92.91% vs 90.06%），但它把**良性的漏检换成了有害的错标**。
做动捕采集，漏检无害（FK 补出来），错标会拽偏 IK。**用 v6**。

阈值设 **0.55**（手指）/ **0.30**（手背）。扫描结果：

```
阈值 0.15(默认): acc 93.03%  harm 6.60%   ← 曲线上最差的工作点之一
阈值 0.50:       acc 91.53%  harm 3.89%
阈值 0.60:       acc 90.15%  harm 2.76%
```

## 3. IK：`Hm20IkRefiner.hpp`

### 为什么必须做

`computeSegmentQuats()` 用 `marker[b]-marker[a]` 当骨轴。球贴在指节背侧、
离骨轴 11~17mm，相邻两节方位角不同，连线**必然**偏离骨轴：

```
骨轴夹角偏差  中位 10.2°  p90 21.6°  最大 53.3°
```

系统偏差，标签 100% 正确也消不掉，滤波去不掉。

### 实测效果（400 帧，1.5mm 观测噪声 + 15% 掉点）

```
分段朝向误差，按该指可见 marker 数分层：
  3点可见  n=3645  中位= 2.68°  p90= 6.40°  最大= 13.59°   ← 主力档
  2点可见  n=1992  中位= 3.92°  p90=10.79°  最大= 43.65°
  1点可见  n= 351  中位= 8.17°  p90=80.13°   ← fingerValid=false
  0点可见  n=  12  中位=72.27°               ← fingerValid=false

fingerValid=true 时 marker 复原误差 1.84mm
耗时 0.44 ms/帧
```

**主力档 10.2° → 2.68°，好 4 倍。**

### 关键：marker 模型必须重写，不能复用现有 fingerFK

`hand/HandModel.hpp` 的 `fingerFK` 把 marker 放在**骨中点**、径向偏置 0：

```cpp
out[0] = (T * transMat(Lp/2, 0, 0)).translation();
```

训练数据 (`hand_rig.py`) 是：

```
local = [L - u,  r*sin(psi),  r*cos(psi)]
```

差异都是系统性的：
- 轴向 `(L-u)/L` 实测均值 **0.632**，不是 0.5
- 径向 `r ≈ 11~16mm`，不是 0 ← **这一项就是那 10° 的主因**

拿现有 `fingerFK` 做 IK 等于让它拟合一个跟观测模型不符的预测，残差消不掉。
`Hm20IkRefiner.hpp` 里的 `markerFK()` 已经按训练数据重写。

### 自由度也对不上

`hand_rig` 每指 **4 个**（MCP屈/MCP展/PIP屈/DIP屈；拇指 CMC屈/CMC展/MCP屈/IP屈），
现有 C++ 是 3 个。少了外展那一维，握拳并指和张星这类姿势拟合不出来。
`Hm20IkRefiner` 用 4 个。

### 精度的硬下界

`u`/`r`/`psi` 是逐人逐指的量，而 `HandTemplateStore` 只存 `backMarkers`。
用群体均值代替的代价实测：

```
marker 位置残差  中位 4.61mm   p90 7.94mm
```

这是"不标定手指"的理论下界。想再压只有让用户做一次手指标定
（张开 + 握拳两个姿势，用 `FingerKinematicCalib` 反解），能到 1~2mm。是否值得由你定。

### 用法

```cpp
#include "Hm20IkRefiner.hpp"

auto ik = std::make_shared<Hm20IkRefiner>();
ik->setHandLenFromBackTemplate(store.backMarkers());
for (int f = 0; f < 5; ++f)
    ik->setFingerParams(f, fingerParam(f).anchor, fingerParam(f).lengths);
assoc.setIkRefiner(ik);

// 每帧
auto R = ik->solve(obsWrist, seen, prevAngles, backTemplate);
for (int f = 0; f < 5; ++f) {
    if (!R.fingerValid[f]) continue;      // 【必须判】否则拿到的是中立位垃圾
    for (int j = 0; j < 3; ++j)
        out.segQuat[1 + 3*f + j] = matToQuat(R.segR[1 + 3*f + j]);
}
prevAngles = R.angles;                    // 时序先验，下一帧用
```

**`fingerValid` 必须判**。某根手指 3 个 marker 全遮挡时 IK 没有任何约束，
输出的是中立位，跟真实姿势可能差 175°。

## 4. 标定：要做，但职责很窄

不是量你的手（手长骨长模型不需要），是**锁住手背相位**。

标签定义 `0号 = 极角最小的点` 踩在刀刃上：`a0` 几乎均匀分布在 [0°, 72°)，
朝向估计偏 10° 就有 15.9% 概率整体循环移位，而移位一格 = **腕部四元数跳 74.3°**。

标定时摆好姿势、点位全可见，此时定下的编号存进 `backMarkers`，
之后每帧只做"离模板哪个点最近"，相位就不会翻。

相位是对是错不重要，只要前后一致：五边形怎么循环移位画出来都一样，
Kabsch 只要求模板和观测用同一套编号。

**手指标定不用做**（只值 1.0 个点，且原理上做不到）。

## 6. 接完之后

`hm20_sim.py --pose` 能测姿态级指标（腕部四元数误差与帧间跳变、手背相位翻转率、
手指分段朝向误差），拿它做接入前后的对照。

但真正的验收只有一条：**采 200~500 帧真机数据手工标**。
到目前为止所有判断都是仿真自己考自己，仿真和现场的差距是唯一没测过的量，
而它大概率比上面所有优化加起来都大。
