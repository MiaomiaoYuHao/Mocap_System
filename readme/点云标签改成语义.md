# 点云标签：追踪序号 → 语义标签

## 效果

点旁边原来是 `1615`、`1424` 这种追踪序号，现在是绿色小写英文：

```
back0  back1  back2  back3  back4          手背 5 点
thumb.mc  thumb.pp  thumb.dp               拇指 掌骨/近节/远节
index.pp  index.mp  index.dp               食指 近节/中节/远节
mid.pp    mid.mp    mid.dp
ring.pp   ring.mp   ring.dp
pinky.pp  pinky.mp  pinky.dp
```

命名对齐 `HandSkeletonAssociator.hpp` 里的 `enum Label`：
`mc`=metacarpal, `pp`=proximal, `mp`=middle, `dp`=distal。
刻意用短名 —— 20 个标签同屏，长名字会糊成一片（实测最长 8 字符）。

---

## 两个设计取舍

### ① 没被认领的点回退显示序号（暗灰）

杂点、幽灵点不会有语义标签。如果一律不画，它们会变成一片没有任何标识的圆点，
反而更难排查"这个多出来的点是哪来的"。所以：

| | 显示 | 颜色 |
|---|---|---|
| 被骨架认领 | `index.dp` | 绿色 `(120,230,120)` |
| 没被认领 | `1615`（序号） | 暗灰 `(140,140,140)`，弱化 |

绿色跟点云的黄、骨架线的橙都分得开。

### ② 只标 `sourcePointId >= 0` 的

补出来的预测点没有对应的点云点。用它的序号去标会指到一个不存在或者已经
被别的点占用的 id 上 —— 那种错不会崩，只会静默标错位置。

---

## 一处容易漏的

`setSkeletonOverlay({}, {})` 在代码里有**两个**调用点（骨架未启用 / 骨架关闭），
两处都补了 `setPointLabels({})`。漏掉任何一处，骨架关掉之后旧标签会一直挂在
点云上、指向早就换掉的追踪 id，看起来就像"标错了"。
