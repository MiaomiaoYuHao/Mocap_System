## 跑出来的数

```
== ① 右手基准（解算手性 = 物理手性）==
   食指: 屈=30.0°  展=12.0°  PIP=-40.0°

== ② 物理左手 + 系统右手档 + 不纠正（= 你现在拿到的数）==
   食指: 屈=-30.0° 展=12.0°  PIP=40.0°

== ③ 同上，但打开 mirrorOut（本次改动）==
   食指: 屈=30.0°  展=12.0°  PIP=-40.0°

39 passed, 0 failed
```

### 三条结论

**① 我上上轮说错了，这次坐实：**
对比 ①②，**屈曲 30 → -30 反号，PIP -40 → +40 反号，外展 12 → 12 一动不动。**
反的是屈曲类，不是外展。我之前让你去 Unity 翻外展维——照做会把对的翻错、错的留着。

**② 纠正是完整的，不只是食指：**
③ 跟 ① 逐位相等。测试里 4 根手指 ×3 维 + **拇指那条特殊分支的 4 维**（`q[0..3]`，
含 IP 耦合）全部断言过了——拇指走的是 `if (f == 0)` 另一个代码路径，单独验的。

**③ 镜像是对合的：**
第 ④ 组验了对右手数据打开 mirrorOut 等于对左手数据关闭，说明这个变换来回一致，
开关拨错了不会产生第三种奇怪状态。

## 顺带测出来一件你可能需要知道的事

**这份代码里 PIP 屈曲是【负】的。** 右手屈 40°，`q[6]` 读出来是 **-40°**。

不是 bug（`hinge` 取的是 `cross(a0, ẑ)`，符号约定如此），但你在 Unity 里映射
PIP/DIP 时要知道这个符号，否则手指会朝反方向弯。MCP 屈曲是正的，两者不一致。

## 仍然没测到的部分

| 项 | 状态 |
|---|---|
| 关节角符号在 `solveJointAngles` 里的行为 | ✅ **已实测** |
| 自动触发条件（`handednessConflict` 判得准不准） | ❌ 依赖真实点云和 4mm 阈值，只有你能验 |
| IK 在左手档下能否生效（上一轮的 anchor 镜像） | ❌ 需要 onnx + 真实观测 |

**所以「自动纠正」这件事，纠正逻辑本身是实测过的，触发它的那个判断没有。**
如果自标定判不出手性（手一直摊平、判据 < 4mm），就不会触发，维持原样——
这是保守设计，但意味着你可能需要手动确认它有没有生效（诊断字段 `jointMirrorActive`）。
