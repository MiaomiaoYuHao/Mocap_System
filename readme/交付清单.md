## 这一轮补的四件

### 1. UI 诊断行（`PointCloudTestDialog.cpp`）

`fullText` 里多一行：

```
手背刚体：内点4/5  残差0.83mm  裕度9.1mm  [连续性仲裁]   自歧义1.77mm ← 贴点布局病态，重贴比调参数管用
手背刚体：未解出 —— 歧义拒解(本帧不给腕部位姿)
```

**自歧义 <3mm 时会直接把那句话打出来。** 这个数一次算完不变，
但它决定你这只手到底能不能被稳定定标签 —— 低于 3mm 的话，
再改多少代码都是在跟一个几何上本来就分不清的问题较劲。

`SkeletonAssocDiag` 相应加了 6 个字段。

### 2. `thumbPronation0` 纳入束调整（`Hm20AutoCalib.hpp`）

新增 `refineThumbPronation()`：粗搜 `[-1.8, 1.8]` 步长 0.1（覆盖 ±103°），
再在最优点附近以 0.02 精搜。

**顺序是先搜常数基线、再搜耦合系数，不能反。** 基线量级 ~80°，耦合项 ~5°；
基线没补上时，耦合项的网格搜是在一个整体偏了 70° 的残差面上找极小值，找到的是噪声。

**门比 `thumbAxialK` 松。** 耦合项 = k × 外展角，外展角小的时候任何 k 都差不多，
所以那个要 `thumbCoverage() >= 0.6`；而常数基线中立位就在起作用，只要拇指有过屈曲就能辨识。

**碗底不明显就不写。** `thumbPronationContrast = sqrt(最差档均方 / 最优档均方)`，
`< 2` 时保持 0（等价旧行为），而不是把一个噪声值写进标定结果。
新增 `AutoCalibConfig::lockedThumbPronation0` —— 这是解剖常数，标一次锁死，别每次会话重搜。

### 3. 收紧 `correctPredictedThumb()`（`HandSkeletonAssociator.hpp`）

改成**只在拇指三颗球全部未观测时**才动手，新增 `thumbFixSkip = 7`。

旧行为是"只转 `observed==false` 的点"。掌骨(5)、近节(6)实测、远节(7)预测 ——
这是最常见的遮挡形态 —— 只转 7，5/6 原地不动，于是

```
近节骨轴 = p7 - p5      远节骨轴 = p7 - p6
```

两个方向都不再有物理意义。你截图里"拇 近节"的相对父节点四元数对应 **118°**，
而拇指 MCP 的解剖限位只有 0.95 rad = **54°** —— 这个数字本身就说明链是断的，不是偏的。

旋前是整条 CMC 后链的刚体自转，只有整条链一起转才自洽。部分遮挡交给
`markerFK` 里的 `thumbPronation0` 去补 —— 那条路是用真实观测约束着解的。

### 4. `K_s` 接进出帧路径（`HandSkeletonAssociator.hpp`）

- `SegSource` 加一档 `Net = 4`
- `applyNetThumbSegments()`：只在几何/IK 都不可信的拇指段上生效，
  `R = wristR · C · segR[s] · K[s-1]`，统一走 `boneFrame`（跟 IK 覆盖同样的理由：
  不同来源的 roll 约定不一样，混着用会让手指在切换源时四元数整个翻过去）
- `SegCanonAligner` 搬进关联器内部 —— 标定要同时看到 `out` 和 `inf`，
  而 `InferenceOutput` 只在 `process()` 里活着，放外面就得把它整个端到 worker 层
- 一键标定：`solveNetSegConstants()` 返回 report，带 `cSpreadDeg` / `kSpreadDeg` / `kOffsetDeg`

**默认关**（`cfg_.thumbSegFromNet = false`）。开之前先看 report：

| 看什么 | 该是多少 | 不对说明 |
|---|---|---|
| `cSpreadDeg` | ≤ 15° | 模板系→规范系不是常数，假设不成立 |
| `kSpreadDeg` | ≤ 15° | 拇指段的修正不是常数，别用 |
| **`kOffsetDeg`** | **70~90°** | 接近 0 或散得离谱 = 前面某个假设错了 |

`kOffsetDeg` 是**交叉验证点**：`probe_thumb_axis.py` 从模型的 `seg_rot6d` 量到拇指铰链轴
缺口是 73°；`kOffsetDeg` 是从**你自己手上的实测几何**反解出来的同一个量。
两条互不依赖的路给出同一个数，才敢接进出帧路径。对不上就别开。
